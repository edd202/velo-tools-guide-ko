<a id="vertex-groups"></a>
## 버텍스 그룹 도구 (Vertex Group Tools)

버텍스 그룹은 정점과 그 영향력 값을 이름으로 묶은 목록입니다. 이름을 바꾸면 해당 그룹을 찾는 본이 달라지고, 웨이트를 바꾸면 정점이 그 본을 따라가는 강도가 달라집니다. 이 탭은 이름을 정리합니다. 값 자체를 옮기려면 Weight Tools를 사용하세요.

### 버텍스 그룹 작업

<a id="vg-merge"></a>
#### 중복 이름 그룹 병합

**7**, **7.001**, **7.003**처럼 점 앞의 이름이 같은 그룹을 합칩니다. 메시를 합친 뒤 유용하지만, 서로 관련 없는 본이 같은 의미인지 알아내는 기능은 아닙니다.

**위치:** Vertex Group Tools → Vertex Group Operations → Merge Vertex Groups.

##### 절차
1. 프로젝트 사본을 저장합니다. Object Mode에서 정리할 메시만 선택합니다.
2. Object Data Properties의 Vertex Groups를 살펴봅니다. 점이 붙은 이름들이 실제로 같은 본에 속하는지 확인합니다.
3. Merge Vertex Groups를 실행합니다. 결과의 기본 그룹을 확인하고 해당 본을 테스트합니다.

##### 간단한 예
소매 메시 두 개를 합쳤습니다. 한쪽은 **7**, 다른 쪽은 **7.001** 그룹을 사용했습니다. 병합하면 할당이 **7** 아래로 모여 하나의 본으로 두 소매 조각을 움직일 수 있습니다. **Arm.L**과 **Arm.R**을 합치는 용도로 사용하지 마세요. 이 이름의 점은 우연한 중복이 아니라 좌우를 구분합니다.

##### 확인 및 복구
점이 붙은 중복 그룹은 사라지고 영향력이 기본 이름으로 옮겨져야 합니다. 웨이트가 정규화되었다고 가정하지 말고 겹치는 웨이트를 확인하세요. 의미가 있는 점 포함 이름이 합쳐졌다면 즉시 실행 취소합니다. 의도적으로 이름을 대응시키려면 [매핑 테이블](#vg-general)을 사용하세요.

<a id="vg-gaps"></a>
#### 숫자 그룹의 빈 번호 채우기 및 정렬

누락된 빈 숫자 그룹을 추가하고 목록을 숫자순으로 정렬합니다. 내보내기 형식이 목록 위치를 본 인덱스로 사용한다면 빈 자리표시자 그룹이 필요할 수 있습니다.

**위치:** Vertex Group Operations → Fill Gaps In Vertex Groups.

##### 절차
1. Object Mode에서 대상 메시를 선택하고 숫자 그룹 이름을 사용하는지 확인합니다.
2. Fill Gaps In Vertex Groups를 실행합니다.
3. 그룹 목록과 몇몇 정점의 할당을 확인합니다.

##### 간단한 예
메시에 **0, 4, 2** 그룹이 있으면 결과는 **0, 1, 2, 3, 4**가 됩니다. **1**과 **3**은 비어 있습니다. 누락된 팔이나 다리 웨이트를 만들어 주지는 않습니다.

##### 확인 및 복구
기존 웨이트는 원래 의도한 그룹에 남아 있어야 합니다. 자리표시자가 필요하다면 직후에 미사용 그룹 제거를 실행하지 마세요. 이 기능은 Component별 로컬 번호를 공통 번호로 변환하지 않습니다. 올바른 [스켈레톤 전략](#game-wwmi-skeleton)을 선택하세요.

<a id="vg-unused"></a>
#### 미사용 그룹 제거

선택한 메시에서 양수 영향력을 갖지 않는 그룹을 제거합니다. 목록을 정리하는 기능이며 작은 웨이트를 지우거나 정점별 영향 본 수를 제한하는 것과는 다릅니다.

**위치:** Vertex Group Operations → Remove Unused Vertex Groups.

##### 절차
1. 프로젝트를 저장하고 목록을 정리할 메시만 선택합니다.
2. 현재 가져오기/내보내기 전략에 빈 숫자 자리표시자가 필요한지 확인합니다.
3. 실행 후 목록을 확인하고 기존 변형을 테스트합니다.

##### 간단한 예
부츠 메시가 전신에서 그룹 이름 200개를 물려받았지만 발목과 발 그룹에만 웨이트가 있습니다. 정리하면 사용하지 않는 항목만 제거되며 부츠가 다른 본으로 옮겨지는 것은 아닙니다.

##### 확인 및 복구
정리 전부터 없던 웨이트는 복구할 수 없습니다. 내보내기에 완전한 번호 목록이 필요하다면 [Fill Gaps](#vg-gaps)를 의도적으로 사용하세요. 값을 바꾸는 [선택 정점 정규화](#weight-normalize)와 구분해야 합니다.

<a id="vg-remove-all"></a>
#### 모든 그룹 제거 후 다시 시작

선택한 메시의 모든 버텍스 그룹을 삭제합니다. 현재 웨이트를 의도적으로 버릴 때만 사용하고, 일반적인 내보내기 문제 해결 방법으로 사용하지 마세요.

**위치:** Vertex Group Operations → Remove All Vertex Groups.

##### 절차
1. 별도 프로젝트 사본을 저장합니다. 원본 참조 바디가 선택되지 않았는지 확인합니다.
2. 교체용 메시에서 Remove All Vertex Groups를 실행합니다.
3. 애니메이션이나 내보내기를 시도하기 전에 원하는 웨이트를 생성하거나 전송합니다.

##### 간단한 예
새로 가져온 액세서리에 다른 리그의 무관한 그룹이 있습니다. 액세서리에서 해당 그룹을 제거한 뒤, 올바르게 웨이트가 설정된 참조에서 머리 또는 손의 적절한 영향력을 전송합니다.

##### 확인 및 복구
목록이 비워지며 Armature 모디파이어가 남아 있어도 본 변형이 멈출 수 있습니다. 버튼이 아마추어 자체를 삭제하지는 않습니다. 참조 웨이트까지 제거했다면 실행 취소하거나 저장한 사본을 다시 엽니다.

### MMD 매핑

<a id="vg-mmd-setup"></a>
#### MMD에서 게임으로의 매핑 설정

**UpperArm.L → 23** 같은 대응표를 만듭니다. 왼쪽 열은 MMD/소스 그룹 이름이고 오른쪽 열은 프로젝트에서 요구하는 게임 측 식별자입니다. 행을 만든다고 웨이트 값이 전송되지는 않습니다.

**위치:** Vertex Group Tools → MMD ↔ Unified ID Mapping.

##### 절차
1. Game에서 게임을 선택하고 내보낼 Component 컬렉션을 설정합니다.
2. MMD Source에 이름이 지정된 참조 메시를, Target Component에 가져온 게임 메시를 지정합니다. 두 메시를 같은 공간에 정렬합니다.
3. 이름 변경 작업으로 소스 본 이름까지 바꾸려는 경우에만 MMD Skeleton을 지정합니다.
4. Mapping Table 텍스트 블록을 만들거나 선택합니다. Fill Rows from Source Object를 클릭합니다. 더하기/빼기로 개별 행을 추가·제거합니다. Clear Mapping Table은 대응표를 비우며 메시 웨이트를 지우지 않습니다.

##### 간단한 예
소매는 **UpperArm.L**, 원본 Component는 **23**을 사용합니다. 두 오브젝트를 각각의 필드에 지정한 뒤 테이블을 채우고 매칭합니다. 유용한 결과는 두 식별자를 연결하고 검토한 행입니다. 다른 모든 행도 올바르다는 보장은 아닙니다.

##### 확인 및 복구
소스 선택기는 내보내기 허용 목록이 아닙니다. 활성 MMD 테이블은 설정된 내보내기 컬렉션 전체의 처리 대상 메시에 그룹 이름을 기준으로 적용됩니다. 정확한 이름을 사용하는 선택기가 빨간색이면 그 오브젝트가 현재 없습니다. X로 지우거나 정확히 같은 이름을 복원하세요. 비슷한 이름의 오브젝트로 대체하지 않습니다.

<a id="vg-mmd-match"></a>
#### 위치로 매칭하고 결과 검토

매처는 각 그룹의 가중 중심, 즉 해당 그룹의 영향력이 집중된 위치를 비교합니다. 중심이 가까우면 대응 가능성을 시사하지만 두 본의 용도가 같다는 증거는 아닙니다.

**위치:** MMD ↔ Unified ID Mapping → Matching Position → Match by position → write to this table.

##### 절차
1. 두 메시의 변형 전 형태가 비교 가능하다면 Rest Position부터 사용합니다.
2. 화면에 보이는 최종 계산 형태가 비교에 적합할 때만 Pose Position을 사용합니다. 이때 양쪽 모두에 Armature, ShapeKey 및 모디파이어 변형이 반영됩니다.
3. 매칭을 실행합니다. 특히 손가락, 얼굴, 겹친 의상 및 좌우 쌍을 포함해 모든 대상 열을 확인합니다.
4. 시각 검토 패널로 확인하고 불확실한 행을 수동 수정합니다. 다시 매칭해야 테이블이 갱신되며 포즈만 바꿔서는 갱신되지 않습니다.

##### 간단한 예
소스의 팔은 내려가 있고 대상의 팔은 올라가 있습니다. 먼저 보이는 포즈를 비교 가능하게 맞춘 뒤 Pose Position을 선택하고 매칭합니다. 왼손목에서 오른손목으로 연결된다면 행을 수정해야 하며 거리 임계값을 늘릴 이유가 아닙니다.

##### 확인 및 복구
매칭은 모디파이어를 적용하거나 지오메트리를 다시 쓰지 않습니다. 웨이트가 없는 그룹이나 특수 보조 그룹은 채워진 행에서 빠질 수 있습니다. 이 편집용 매처는 [원본 본 이름 보조 파일](#vg-wwmi-map)을 생성할 때 사용하는 전체 스킨 웨이트 검증 매칭과 다릅니다.

<a id="vg-mmd-rename"></a>
#### 네 가지 이름 변경 버튼 중 올바른 버튼 선택

이 버튼들은 서로 다른 두 메시에 작용합니다. ‘소스’와 ‘대상’은 위쪽 필드를 뜻하며, 뷰포트에서 우연히 선택된 메시를 뜻하지 않습니다.

**위치:** MMD ↔ Unified ID Mapping → 이름 변경/복원 작업 두 줄.

##### 절차
1. 이름을 변경하기 전에 매핑 테이블을 검토하고 저장합니다.
2. 아래 표에서 처리할 쪽과 방향을 선택합니다.
3. 버텍스 그룹 이름과, 지정했다면 소스 아마추어도 확인합니다. 유일한 사본에 덮어쓰기 전에 변형을 테스트합니다.

| 작업 | 동작 |
| --- | --- |
| Rename source to unified number | MMD 소스 그룹을 오른쪽 열의 식별자로 변경합니다. 지정된 소스 본도 변경할 수 있습니다. |
| Restore source to MMD name | 원래 그룹 이름, 순서, 웨이트를 포함한 소스 스냅샷을 복원합니다. |
| Rename target to MMD name | 대상 Component에 소스 측 이름과 매핑 테이블 순서를 적용합니다. |
| Rename target to unified number | 현재 순서를 유지하면서 대상 그룹을 게임 식별자로 되돌립니다. |

##### 간단한 예
숫자 이름으로 가져온 Component를 읽기 쉬운 소스 이름으로 웨이트 페인팅하려면 **Rename target to MMD name**을 사용합니다. 소스 버튼을 누르면 참조의 이름이 바뀝니다.

##### 확인 및 복구
소스 복원은 단순히 이름만 역변경하는 작업이 아닙니다. 이전 웨이트까지 복원할 수 있습니다. 스냅샷 이후의 웨이트 편집이 복원 후에도 남을 것이라고 기대하지 마세요. 내보내기 전처리는 이미 임시 사본에서 수행하므로 내보내기만을 위해 파괴적인 영구 이름 변경을 할 필요는 없습니다.

<a id="vg-table-save"></a>
#### 매핑 테이블 저장·불러오기·재사용

검토한 대응표를 blend 내부 또는 외부 텍스트 파일에 보관합니다. 저장한 테이블에는 대응 관계가 담기며 메시, 텍스처 또는 전체 리그 백업은 포함되지 않습니다.

**위치:** MMD 또는 General Mapping → Mapping Table, Built-in Text 동기화, Import/Export Mapping Text.

##### 절차
1. 패널 상단에서 원하는 텍스트 블록을 만들거나 선택합니다.
2. 행을 수정한 뒤 **to Built-in Text** 화살표를 클릭하고 blend를 저장합니다.
3. Blender Text Editor에서 텍스트를 편집했다면 **from Built-in Text** 화살표로 행을 다시 불러옵니다.
4. 별도 파일로 저장하려면 Export Mapping Text, 재사용하려면 Import Mapping Text를 사용합니다. 바꾸기 전에 현재 선택된 테이블을 확인합니다.

##### 간단한 예
프로젝트에 **Sleeve mapping**이라는 테이블을 저장합니다. 다른 프로젝트에서 내보낸 텍스트를 가져온 뒤, 대상 번호가 여전히 같은 추출 캐릭터와 스켈레톤 모드를 가리키는지 확인합니다.

##### 확인 및 복구
MMD 테이블과 General 테이블은 선택기와 작업 오브젝트가 독립적이므로 구분해 보관합니다. 빈 행, 중복 또는 충돌하는 행은 검토해야 합니다. 이전 테이블을 가져왔다고 새 덤프에서도 번호가 유효한 것은 아닙니다. 유용한 테이블을 비우거나 교체하기 전에 백업을 내보내세요.

### 일반 매핑 및 시각 검토

<a id="vg-general"></a>
#### 임의의 두 메시 사이에서 그룹 이름 변경

General Vertex Group Mapping은 게임에 종속되지 않는 버전입니다. MMD 명명 규칙이나 숫자 게임 그룹 없이 한 이름 집합을 다른 집합에 대응시킵니다.

**위치:** Vertex Group Tools → General Vertex Group Mapping.

##### 절차
1. 위쪽 MMD 필드가 아닌 이 패널의 Source Object, Target Object 및 선택적인 Skeleton을 설정합니다.
2. Rest 또는 Pose Position을 선택하고 소스에서 행을 채운 뒤 위치로 매칭합니다.
3. 모델 크기에 적합한 거리를 알고 있다면 최대 거리 제한을 켭니다. 임의의 먼 매칭을 받아들이지 말고 거부된 행을 수정합니다.
4. 상황에 맞게 Source → Target names, Restore Source, Target → Source names 또는 Target → Target names를 적용하고 테이블을 저장합니다.

##### 간단한 예
소스 장갑에는 **finger_index_01**이 있지만 리그는 **Index1.L**을 요구합니다. 장갑과 대상 손을 정렬하고 해당 행을 검토한 뒤 원하는 쪽의 이름을 변경합니다. 장갑에 칠한 값은 그대로이며 대상 손의 웨이트를 샘플링하지 않습니다.

##### 확인 및 복구
연결된 스켈레톤은 이름을 함께 변경하기 위한 것입니다. 실제 포즈 공간 비교에는 각 메시의 변형 스택이 사용됩니다. General 매핑은 활성 MMD 내보내기 매핑과 호환되지 않습니다. 여러 관절이 밀집해 있다면 구조를 알고 있는 사람이 행을 채우고 [연결을 확인](#vg-review)하세요.

<a id="vg-review"></a>
#### 중심 연결선과 미매칭 목록 사용

시각 검토는 소스와 대상 그룹 중심 사이의 연결선을 표시합니다. 이름을 바꾸기 전에 좌우 교차나 먼 거리의 추정 매칭을 찾는 데 도움이 됩니다.

**위치:** MMD 또는 General Mapping 아래의 시각 검토 패널. General Mapping에는 Unmatched List도 있습니다.

##### 절차
1. 첫 매핑을 끝내고 해당 패널의 오버레이를 켭니다.
2. 라벨과 매칭되지 않은 대상 점을 표시합니다. 화면이 복잡하면 표시할 연결선 거리를 조절합니다.
3. 모델 주위를 돌며 여러 각도에서 손목, 어깨, 손가락, 중심선을 살펴봅니다.
4. 행을 수정하고 의도한 경우에만 다시 매칭한 뒤 재검토합니다. 끝나면 오버레이를 끕니다.

##### 간단한 예
왼쪽 소매의 연결선이 몸통을 가로질러 오른팔 그룹으로 이어집니다. 해당 행의 소스/대상 이름을 확인하고 올바른 왼쪽 식별자로 바꿉니다. 겹친 의상 레이어는 중심을 공유할 수 있으므로 짧은 선만으로 올바른 매칭을 증명할 수는 없습니다.

##### 확인 및 복구
MMD와 General 오버레이는 서로 겹쳐 그려지지 않도록 동작합니다. Pose Position에서 포즈를 움직이면 선은 갱신되지만 저장된 할당은 바뀌지 않습니다. 빈 라벨이나 미매칭 항목이 있으면 웨이트 정규화가 아니라 행/오브젝트를 확인하세요.

<a id="vg-pick"></a>
#### 오버레이 점 클릭 또는 매핑 드래그

표시된 매핑 점은 조작할 수 있습니다. 클릭은 그룹 웨이트를 확인하고 드래그는 대응 관계를 편집합니다. 서로 다른 작업입니다.

**위치:** MMD 또는 General Mapping → 시각 검토 오버레이 활성화 → 3D Viewport.

##### 절차
1. 소스와 대상 메시를 선택한 뒤 올바른 오버레이를 켭니다.
2. 그룹 끝점을 클릭해 해당 메시/그룹의 Weight Paint로 들어가 영향력을 확인합니다.
3. 소스 끝점을 올바른 대상 끝점으로 끌어 매핑 행을 기록합니다.
4. 이후 테이블을 확인합니다. 끝나면 오버레이를 끄거나 웨이트 페인팅 세션을 종료합니다.

##### 간단한 예
소매의 소스 점이 잘못된 팔에 연결되어 있습니다. 그 끝점을 올바른 대상으로 끌고 갱신된 테이블을 확인합니다. 이미 연결된 대상 점을 다른 대상 점으로 끌면 그 점에 연결된 대응들이 재지정되므로 영향을 받는 모든 행을 검토하세요.

##### 확인 및 복구
소스 점을 빈 공간에 놓으면 대상 연결이 지워집니다. 드래그 취소 동작이 아닙니다. 이미 연결된 대상 점을 빈 공간에 놓으면 그대로 유지됩니다. 확인 중에는 선택기가 강도 0의 빼기 브러시를 임시 사용하고 세션이 끝나면 저장한 브러시 상태를 복원합니다. 실제로 칠하기 전에 브러시를 확인하세요. 클릭으로 웨이트가 이동했다고 가정하지 마세요.

### WWMI 원본 본 이름

<a id="vg-wwmi-map"></a>
#### WWMI 원본 본 이름 생성 및 저장

읽기 어려운 WWMI 숫자 그룹을 검증된 원본 본 이름 대응표로 바꿉니다. 일치하는 언팩 모델이 필요합니다. Velo가 숫자만으로 본 이름을 복원하지는 않습니다.

**위치:** Vertex Group Tools → WWMI Numeric ID ↔ Original Bone Name. Game에서 Wuthering Waves를 선택합니다.

##### 절차
1. Unpack Folder에 일치하는 .uemodel 에셋을, Object Source Directory에 WWMI 추출물을 지정합니다.
2. 첫 시도에는 유사도와 복셀 크기의 기본값을 유지하고 Generate Mapping Table을 클릭합니다.
3. 결과를 검토합니다. 1.7.1은 대응하는 스킨 웨이트 행 전체를 검사하며, 먼 메시뿐 아니라 모호한 본 식별도 거부합니다.
4. Save Matching Results to Source Directory를 클릭합니다. **WWMI_MatchingResult.json**을 추출 소스와 함께 보관합니다. Load Mapping Table from Source Directory로 저장한 결과를 복원할 수 있습니다.

##### 간단한 예
몸통과 소매가 여러 본을 공유하며 그 영향을 받는 정점이 겹칩니다. 전체 웨이트 패턴은 중심만 비교했을 때 뒤바뀔 수 있는 식별자를 구분합니다. 성공한 결과는 나중에 원래 언팩 폴더가 없어도 이름과 저장된 스켈레톤을 제공할 수 있습니다.

##### 확인 및 복구
이전 v1 결과는 올바른 언팩 에셋에서 v2로 다시 생성해야 합니다. 유사도 임계값을 바꾼다고 모호한 본 식별이 증명되는 것은 아닙니다. 무관한 Component나 다른 캐릭터의 행을 수동 복사해 실패를 해결하지 마세요.

<a id="vg-wwmi-bind"></a>
#### 이름 전환 또는 WWMI 스켈레톤 바인딩

저장한 대응표로 가져온 프로젝트의 포즈 작업을 편하게 합니다. 이름 전환은 선택한 메시에 적용되지만 원클릭 바인딩은 설정된 Component 컬렉션 전체를 대상으로 합니다.

**위치:** WWMI Numeric ID ↔ Original Bone Name.

##### 절차
1. 앞선 튜토리얼에 따라 유효한 매핑을 생성하거나 불러옵니다.
2. 일부만 바꾸려면 원하는 메시를 선택하고 Switch to original name 또는 Switch to numeric numbering을 사용합니다.
3. 아마추어만 필요하면 Import Skeleton을 사용합니다. Mirror Skeleton이 가져오기 방향과 일치하는지 확인합니다.
4. Bind Skeleton to Mod Mesh로 설정된 WWMI Component 컬렉션을 처리하고 바인딩합니다. 선택적인 .L/.R 변환은 지원되는 것으로 감지된 쌍만 변경합니다.

##### 간단한 예
먼저 가져온 소매 하나를 원본 이름으로 전환해 팔 그룹을 확인합니다. 다음으로 전체 Mod 컬렉션을 바인딩하고 위팔 본을 조금 회전해 소매가 올바르게 따라가는지 확인합니다.

##### 확인 및 복구
테이블에 행을 추가해도 검증된 식별이 성립하지는 않습니다. 사용되는 매핑이 모호하면 작업이 중단됩니다. 추출물, 저장된 매핑, 스켈레톤 스냅샷을 함께 보관하세요. 이름을 바꾼 메시를 내보낼 준비가 되었다고 판단하기 전에, 일치하는 가져오기/내보내기 번호 전략으로 돌아가 확인하세요.


<a id="mesh"></a>
## 메시 도구 (Mesh Tools)

편집할 오브젝트를 준비합니다. 분리된 조각을 함께 스컬프팅하고, 머티리얼과 컬렉션을 정리하며, ShapeKey를 관리합니다. 여기의 머티리얼 보조 기능은 지오메트리를 정리합니다. 게임에 전달할 텍스처는 별도의 Material Tools 탭에서 제어합니다.

### 스컬프팅 및 머티리얼 정리

<a id="mesh-sculpt"></a>
#### 여러 오브젝트를 하나처럼 스컬프팅하고 편집 결과 되돌려 보내기

분리된 조각의 경계를 넘어 브러시를 사용할 수 있도록 임시 병합 오브젝트를 만듭니다. 완성된 위치는 원본 오브젝트로 전달됩니다.

**위치:** Mesh Tools → Multi-Object Sculpt.

##### 절차
1. 사본을 저장하고 Object Mode에서 원본 메시들을 선택한 뒤 Create Merged Object를 클릭합니다.
2. 기존 정점을 움직이는 브러시로 병합 오브젝트를 스컬프팅합니다. 이 작업 중에는 리메시, Dyntopo, 정점 삭제 또는 원본 토폴로지 변경을 하지 마세요.
3. Apply Merged Object Sculpt로 결과를 원본에 전달합니다.
4. 원본에 ShapeKey가 있다면 Apply Merged Object Sculpt (Shape Keys)를 선택합니다. 위치 변화가 각 키에도 더해집니다.

##### 간단한 예
셔츠가 몸통과 소매 두 개로 구성되어 있습니다. 병합 스컬프팅 오브젝트를 만들어 연결 부분을 매끄럽게 합니다. 키가 없다면 일반 적용을 사용합니다. 호흡 키도 있는 셔츠라면 Shape Keys 작업을 사용하고 해당 키를 테스트합니다.

##### 확인 및 복구
각 원본을 따로 확인하고 키 값을 0과 1로 테스트합니다. 이 작업은 정점 대응 관계에 의존합니다. 새 정점이 가까워 보인다고 안정적으로 되돌려 보낼 수는 없습니다. 토폴로지가 달라졌다면 실행 취소하거나 저장한 사본을 다시 여세요.

<a id="mesh-prefix"></a>
#### 교체용 메시에 Component 식별자 부여

**Component N**으로 시작하는 이름은 메시가 어떤 추출 파트에 속하는지 익스포터에 알려줍니다. 번호는 소스 식별자이며 자유롭게 고르는 정리용 라벨이 아닙니다.

**위치:** Mesh Tools → Material Tool → Add the Component prefix to the selected object.

##### 절차
1. 가져온 참조와 일치하는 오브젝트 소스에서 대상 Component를 확인합니다.
2. 교체용 메시들을 선택하고 버튼 옆에 번호를 지정합니다.
3. 실행 후 최종 오브젝트 이름을 확인합니다. 설정된 내보내기 컬렉션 안에 둡니다.

##### 간단한 예
참조 소매가 실제로 Component 2에 속한다면 **Sleeve**라는 메시에 **2**를 추가합니다. 결과 이름은 그 메시가 Component 2에 속함을 나타냅니다. 무관한 Component의 웨이트를 호환되게 만들지는 않습니다.

##### 확인 및 복구
예제 번호를 그대로 복사하지 마세요. Auto Split by Material이 켜져 있으면 머티리얼 접두사도 분류에 영향을 줄 수 있습니다. 꺼져 있다면 오브젝트 자체의 Component 이름만 전체 오브젝트의 소속을 결정합니다. [내보내기 범위](#game-scope)를 참고하세요.

<a id="mesh-material-name"></a>
#### 텍스처 연결을 유지하면서 같은 이름의 머티리얼 생성

처리하는 오브젝트에 그 이름을 따르는 머티리얼을 부여합니다. 머티리얼 기준 분리에서 Component를 인식하기 쉬워지고 프로젝트도 읽기 쉬워집니다.

**위치:** Mesh Tools → Material Tool → Generate a material ball for selected objects.

##### 절차
1. Object Mode에서 대상 메시들을 선택합니다.
2. 첫 번째 유효한 머티리얼 슬롯을 확인합니다. 기존 연결이 보존되는 머티리얼은 이 슬롯입니다.
3. 실행 후 오브젝트, 메시, 머티리얼 이름과 표시되는 텍스처를 확인합니다.

##### 간단한 예
**Component 2 Sleeve** 오브젝트가 여전히 **Material.018**을 사용합니다. 실행하면 편집한 머티리얼에 유용한 동일 이름을 부여하면서 디퓨즈 이미지와 원본 텍스처 매핑을 유지합니다.

##### 확인 및 복구
편집된 머티리얼이 원래 이름을 우선 사용하며, 보존된 이전 머티리얼에는 **Backup …** 이름이 붙을 수 있습니다. 다른 사용 오브젝트의 머티리얼 내용과 할당은 유지됩니다. DATA 및 OBJECT 연결 슬롯을 지원하므로 이름을 고치려고 연결 유형부터 수동으로 바꾸지 마세요. 뒤쪽의 서로 다른 슬롯과 면 할당을 모두 하나의 머티리얼로 합치라는 뜻은 아닙니다.

<a id="mesh-auto-name"></a>
#### 오브젝트 이름 변경에 맞춰 머티리얼 이름 동기화

머티리얼 생성 옆의 작은 새로고침 모양 토글이 이후 이름 변경을 감시합니다. 기본값은 꺼짐이며 상태는 씬에 저장됩니다.

**위치:** Mesh Tools → Material Tool → Generate a material ball 옆 아이콘.

##### 절차
1. 현재 게임의 내보내기 Component 컬렉션을 설정합니다.
2. 아이콘 토글을 켭니다. 켜지면 Blender의 강조 상태로 표시됩니다.
3. 해당 컬렉션 또는 하위 컬렉션 안의 기존 메시 이름을 바꿉니다.
4. 메시와 머티리얼이 새 이름을 따르는지 확인합니다.

##### 간단한 예
단일 머티리얼 오브젝트를 **Component 2 Sleeve**에서 **Component 2 LongSleeve**로 바꾸면 이름이 자동으로 따라갑니다. 새 복제본은 우선 수정 없이 기록되며 이후 이름을 변경할 때 동기화됩니다.

##### 확인 및 복구
머티리얼 슬롯이 0개 또는 1개인 메시만 자동 처리합니다. 여러 머티리얼이 있는 메시는 의도적으로 건너뜁니다. 내보내기 컬렉션 밖의 오브젝트는 감시하지 않습니다. 이미 어긋난 이름을 즉시 고치려면 [수동 머티리얼 생성](#mesh-material-name)을 사용하세요.

<a id="mesh-split"></a>
#### 머티리얼별 분리 및 빈 ShapeKey 정리 제어

머티리얼에 따라 면을 오브젝트로 분리합니다. 옆의 임계값은 분리된 조각의 정점을 거의 움직이지 않는 ShapeKey를 유지할지 결정합니다.

**위치:** Mesh Tools → Material Tool → Separate by material; ShapeKey Cleanup Threshold.

##### 절차
1. 사본을 저장하고 각 면의 머티리얼 할당을 확인합니다. 분리는 겉모습이 아닌 할당을 따릅니다.
2. 정리 임계값을 설정합니다. 기본값은 로컬 좌표 거리 **0.0001**입니다. 의도한 미세 움직임을 보존하려면 더 작은 값을 사용합니다.
3. 메시들을 선택하고 Separate by material을 실행합니다.
4. 조각과 남은 키를 확인합니다. 분리는 Basis에서 시작하며 결과 조각도 Basis 상태로 둡니다.

##### 간단한 예
셔츠에 소매와 단추 머티리얼이 있습니다. 분리 후 단추의 모든 움직임이 임계값보다 작다면 소매 전용 키를 단추 오브젝트에서 제거할 수 있습니다. 의도적인 작은 단추 움직임은 충분히 낮은 임계값이 필요합니다.

##### 확인 및 복구
임계값은 조각에서 사실상 빈 키를 삭제할 수 있지만 이미 오염된 키를 복구하지는 않습니다. 큰 값은 실제 미세 변형을 버릴 수 있으므로 필요하면 실행 취소하고 낮추세요. Basis를 기준으로 분리하면 나중에 합칠 때 없는 키를 잘못된 활성 형태로 채우는 일을 막습니다.

<a id="mesh-merge"></a>
#### 같은 이미지 집합을 사용하는 오브젝트 병합

머티리얼이 동일한 이미지 집합을 사용하는 선택 메시들을 합쳐 오브젝트 수를 줄입니다. 이미지 패킹이나 머티리얼 슬롯 중복 제거 기능은 아닙니다.

**위치:** Mesh Tools → Material Tool → Merge according to textures.

##### 절차
1. Object Mode에서 대상 메시를 둘 이상 선택합니다.
2. 디퓨즈뿐 아니라 머티리얼에서 사용하는 모든 이미지를 확인합니다.
3. 병합 후 결과 오브젝트, 머티리얼 슬롯, ShapeKey를 확인합니다.

##### 간단한 예
천 조각 세 개는 같은 디퓨즈와 노멀 이미지를 사용하고 버클은 별도 이미지를 사용합니다. 천 그룹은 합칠 수 있지만 버클은 따로 남습니다. 머티리얼 슬롯은 유지되며 단일 셰이더로 합쳐지지 않습니다.

##### 확인 및 복구
텍스처가 없는 메시는 큰 그룹으로 합치지 않고 건너뜁니다. 디퓨즈가 같아도 추가 이미지가 다르면 동일 이미지 집합이 아닐 수 있습니다. 특히 내보내기 전에 최종 Component 이름과 실제 컬렉션 소속을 확인하세요.

<a id="mesh-contamination"></a>
#### 반복된 ShapeKey 오염을 보수적으로 정리

무관한 ShapeKey에 복사된, 완전히 동일하고 머티리얼 영역 전체에 걸친 반복 변위를 제거하려고 시도합니다. 범위가 좁은 휴리스틱 복구 기능이며 ‘모든 ShapeKey 복구’ 기능은 아닙니다.

**위치:** Mesh Tools → Material Tool → Clean ShapeKey Contamination.

##### 절차
1. 사본을 저장하고 Object Mode에서 영향을 받은 메시들을 선택합니다.
2. 여러 키에서 의심스러운 공통 변형을 확인합니다.
3. 실행 후 보호된 소스, 복구, 건너뛴 항목의 수를 읽습니다.
4. 변경된 모든 키를 테스트합니다. 의도한 반복이었다면 실행 취소합니다.

##### 간단한 예
독립적인 **SleeveLift** 키 자체는 올바르지만 소매 전체의 똑같은 변위가 서로 다른 다른 키에도 들어 있습니다. 도구가 최소 세 개 키에 걸쳐 보호할 원본과 반복 영역을 식별할 수 있다면, 순수하게 추가된 해당 영역만 Basis로 되돌릴 수 있습니다.

##### 확인 및 복구
다르거나 중첩된 움직임을 근사적으로 빼지 않습니다. 모호한 패턴은 건너뛰고 키를 삭제하지 않으며 옆의 정리 임계값도 사용하지 않습니다. 공유/읽기 전용 메시, 부적절한 키 관계, 너무 큰 스냅샷은 건너뛸 수 있습니다. 의도적으로 재사용한 동일 변형도 오염처럼 보일 수 있으므로 복구 개수만 믿지 말고 결과를 확인하세요.

### 메시 유틸리티

<a id="mesh-fill"></a>
#### 누락된 기본 메시 데이터 채우기

새 메시가 필요한 기본 레이어를 갖도록 누락된 **COLOR**와 **TEXCOORD.xy** 데이터를 생성합니다. 빈 UV는 자리표시자이며 완성된 텍스처 언랩이 아닙니다.

**위치:** Mesh Tools → Material Tool → Utilities → Fill Missing Mesh Data.

##### 절차
1. 새 메시들을 선택하고 Object Data Properties를 확인합니다.
2. Fill Missing Mesh Data를 실행합니다.
3. 필요한 UV/색상 레이어가 있는지 확인하고 필요에 따라 언랩하고 데이터를 만듭니다.

##### 간단한 예
새로 만든 벨트에 UV와 색상 레이어가 없습니다. 실행하면 빈 기본 UV와 검은 COLOR를 만듭니다. 디퓨즈 이미지를 제대로 표시하려면 여전히 벨트를 언랩해야 합니다.

##### 확인 및 복구
소스별 패킹 데이터, 노멀, 본 웨이트를 복원하지는 않습니다. 두 레이어로 충분하다고 판단하기 전에 대상 Component의 실제 레이아웃을 확인하세요. 레이아웃에서 요구하는 경우에만 적절한 스무스 노멀 생성기를 사용합니다.

<a id="mesh-modifiers"></a>
#### ShapeKey가 있는 메시에 선택한 모디파이어 적용

Blender의 일반 Apply가 ShapeKey 때문에 거부하는 메시에도 모디파이어를 적용합니다. 각 키에서 호환되는 지오메트리가 생성되어야 합니다.

**위치:** Mesh Tools → Utilities → Apply Modifiers For Object With Shape Keys.

##### 절차
1. 별도 사본을 저장하고 대상 메시를 활성화합니다.
2. 작업 대화상자를 열고 적용할 모디파이어만 체크합니다.
3. 의도적으로 포즈를 굽는 경우가 아니라면 Don't include armature deformations를 켜 둡니다.
4. 적용 후 모디파이어 스택과 중요한 모든 키를 테스트합니다.

##### 간단한 예
표정과 무관한 핏 조정 키가 이미 있는 대칭 의상에 Mirror를 적용하고 싶습니다. Mirror만 적용하고 Basis와 각 핏 키를 양쪽에서 비교합니다.

##### 확인 및 복구
토폴로지를 바꾸는 모든 스택이 키 간 호환되는 것은 아닙니다. 드라이버/키프레임 같은 ShapeKey 애니메이션 데이터가 손실될 경우 대화상자에 경고가 표시됩니다. 그 데이터를 위해 프로젝트 백업을 보관하세요. 오류가 보고되거나 키가 깨졌다면 성공한 베이크가 아닙니다. 실행 취소하거나 저장 사본을 사용합니다.

<a id="mesh-linear"></a>
#### 버텍스 색상 저장 방식을 Linear로 변환

COLOR/COLOR1 레이어를 도구 체인에서 요구하는 저장 규약으로 바꿉니다. 데이터 형식 변환이며 새로운 표시 색상을 고르는 기능은 아닙니다.

**위치:** Mesh Tools → Utilities → Convert Vertex Colors To Linear.

##### 절차
1. 프로젝트를 저장하고 관련 메시들을 선택합니다.
2. 어떤 COLOR/COLOR1이 가져온 데이터이고 어떤 것이 직접 칠한 것인지 확인합니다.
3. 작업 흐름에 Linear 저장이 필요할 때만 변환합니다.
4. 레이어를 확인하고 비교용으로 내보낸 뒤 넓은 범위에 적용합니다.

##### 간단한 예
이전 프로젝트에서 가져온 메시가 예전 색상 저장 방식을 사용합니다. 보존한 참조가 아닌 복제본만 선택해 변환하고 같은 게임 조명에서 내보낸 색상 동작을 비교합니다.

##### 확인 및 복구
누락된 외곽선 노멀을 생성하거나 게임 채널의 의미를 알려주지 않습니다. Blender에서 이상해 보인다는 이유로 패킹 데이터를 다시 칠하지 마세요. 대상 셰이더 결과를 확인할 때까지 원본을 보관합니다.

### UV 및 외곽선 노멀 데이터

<a id="mesh-octahedral"></a>
#### TEXCOORD1에 스무스 노멀 생성

해당 규약을 요구하는 셰이더를 위해 UV 레이어에 부드러운 방향 데이터를 저장합니다. 텍스처 아일랜드를 옮기는 것이 아니라 추가 셰이딩 지침을 기록한다고 생각하세요.

**위치:** Mesh Tools → UV Tool → Smooth Normal - Octahedral UV.

##### 절차
1. 대상 셰이더/내보내기 레이아웃이 이 데이터를 요구하는지 확인합니다.
2. 선택한 각 메시에 첫 번째 UV 레이어가 이미 있는지 확인합니다. 그 UV가 방향의 기준을 정의합니다.
3. 기존 **TEXCOORD1.xy**를 백업하고 생성기를 실행합니다.
4. 내보내고 특히 경계부의 외곽선을 살펴봅니다.

##### 간단한 예
호환되는 작업 흐름에서 새 저폴리 액세서리의 외곽선이 각져 보입니다. 사본에 추가 스무스 방향을 생성하고 전후 실루엣을 비교하면서 바깥 경계와 원래 텍스처 방향을 함께 확인합니다.

##### 확인 및 복구
TEXCOORD1.xy를 생성하거나 교체합니다. 모든 게임에 통하는 외곽선 해결책은 아닙니다. 기본 UV 방향을 바꾸면 인코딩된 방향도 바뀝니다. Endfield 소스 레이아웃이 다른 저장 채널을 요구하면 아래 전용 기능을 사용하세요.

<a id="mesh-texcoord4"></a>
#### TEXCOORD4에 Endfield 스무스 노멀 생성

일부 Endfield Component는 스무스 노멀 X/Y를 **TEXCOORD4.xy**에 저장합니다. 이 생성기는 새 지오메트리에 해당 표현을 준비합니다.

**위치:** Mesh Tools → UV Tool → Generate Smooth Normal TEXCOORD4.

##### 절차
1. 추출한 Component의 .fmt와 보존된 참조 레이어를 확인합니다.
2. 가져온 원본 보조 데이터는 가능한 한 유지합니다. 새 메시에는 기본 **TEXCOORD.xy** UV를 준비합니다.
3. 새 파트를 Component에 합치기 전에 생성기를 실행합니다.
4. 내보낸 게임 결과의 외곽선을 확인합니다.

##### 간단한 예
새로 모델링한 커프스를, 외곽선 노멀에 TEXCOORD4를 사용하는 Endfield Component에 합칩니다. 기존 소매에 작성된 레이어는 유지하고 커프스 레이어부터 생성합니다.

##### 확인 및 복구
위치가 정확히 겹치는 중복 정점은 UV 아일랜드를 합치지 않고 함께 스무딩합니다. 기존 TEXCOORD4는 덮어씁니다. 삭제한 원본 베이크 데이터를 비트 단위로 복원하지는 못하므로 새 파트 하나를 채우려고 원본 모델 전체에 실행하지 마세요.

<a id="mesh-color-normal"></a>
#### COLOR 외곽선 노멀 생성 및 사용 설정

Endfield Component가 호환되는 스무스 노멀 표현을 패킹된 COLOR에 저장할 때만 사용합니다. COLOR는 데이터 컨테이너이며 모든 Component에서 용도가 같지는 않습니다.

**위치:** Mesh Tools → Vertex Color Tool → Generate Smooth Normal COLOR; Enable COLOR Outline Normals.

##### 절차
1. 앞 튜토리얼처럼 소스 레이아웃과 보존된 참조 데이터를 검증합니다.
2. 새 지오메트리를 선택하고 COLOR를 생성합니다. 생성하면 사용 설정 체크박스가 자동으로 켜집니다.
3. 호환되는 COLOR가 이미 작성되어 있다면 재계산 없이 체크박스만 켭니다.
4. 전체 내보내기로 mod.ini를 다시 생성한 뒤 외곽선을 확인합니다.

##### 간단한 예
새 커프스가 호환되는 COLOR 레이아웃을 사용합니다. 수동으로 칠하기 전에 생성하세요. 이후 다시 생성하면 칠한 COLOR가 덮어써집니다.

##### 확인 및 복구
가져온 COLOR는 기본적으로 게임의 기본 제어를 따릅니다. 체크를 해제해도 일반 COLOR 내보내기를 막지 않으며 게임에서 이미 켠 선택자를 무효화하지도 않습니다. 내보낸 파트 하나가 사용을 설정하면 같은 Component의 호환되는 커스텀 드로우가 활성화될 수 있습니다. 호환되지 않는 레이아웃과 다른 보호 경로는 기본 동작을 유지합니다. 외곽선 두께 슬라이더나 범용 투명도 마스크가 아닙니다.

### 컬렉션 분류

<a id="mesh-route-preview"></a>
#### 컬렉션 트리에서 머티리얼 파트 배치 계획

실제로 분리하기 전에 머티리얼별 조각의 목적지를 미리 봅니다. 컬렉션 행은 실제 Blender 컬렉션이고 머티리얼 말단 항목은 계획된 그룹이며 반드시 기존 오브젝트인 것은 아닙니다.

**위치:** Mesh Tools → Split into Collections by Material.

##### 절차
1. 현재 게임의 내보내기 Component 컬렉션을 설정합니다.
2. Refresh Material Groups를 클릭합니다.
3. 더하기로 하위 컬렉션을 추가하고 머티리얼 말단 항목을 선택합니다.
4. 목적지 컬렉션의 가져오기/할당 아이콘을 클릭해 계획 그룹을 이동합니다. 펼침 화살표는 확장/축소용이며 할당용이 아닙니다.

##### 간단한 예
합쳐진 의상에 천과 장식 머티리얼이 있습니다. **Cloth**, **Trim** 하위 컬렉션을 만들고 분리 전에 각 가상 말단 항목을 원하는 폴더에 할당합니다.

##### 확인 및 복구
하위 컬렉션을 제거하면 계획 그룹이 상위로 돌아가며 메시를 지우지 않습니다. 이미 분리된 오브젝트는 Outliner 이동을 포함한 실제 컬렉션 소속을 따릅니다. 오래된 미리보기를 믿기 전에 새로고침하세요. 새 하위 컬렉션도 내보내도록 이 작업들이 Ignore Nested Collections를 끌 수 있습니다.

<a id="mesh-route-apply"></a>
#### 계획한 컬렉션으로 분리하거나 텍스처별 그룹화

미리보기를 실제 분리 오브젝트로 만듭니다. 머티리얼 작업은 머티리얼별 조각을 유지합니다. 텍스처 작업은 같은 이미지 집합을 사용하는 조각을 추가로 합쳐 오브젝트 수를 줄이려고 시도합니다.

**위치:** Split into Collections by Material → 두 가지 분리 작업.

##### 절차
1. [컬렉션 계획](#mesh-route-preview)을 마치고 사본을 저장합니다.
2. 머티리얼별 조각을 분리해서 유지하려면 Split by Material into Collections를 선택합니다.
3. 호환되는 오브젝트 수를 줄이려면 대신 텍스처/그룹화 작업을 선택합니다.
4. Outliner에서 실제 오브젝트와 이름, 머티리얼, ShapeKey를 확인합니다.

##### 간단한 예
커프스와 소매를 독립 편집하려면 머티리얼 분리를 사용합니다. 여러 장식 조각이 정확히 같은 이미지를 사용하고 목적지도 같다면 텍스처 방식으로 묶을 수 있습니다.

##### 확인 및 복구
내보내기 중의 임시 분리와 달리 실제 편집 데이터가 바뀝니다. Basis 우선 준비도 적용됩니다. 수동 이동 이후에는 분리된 조각의 실제 소속이 기준입니다. 오래된 가상 항목이 예전의 숨겨진 컬렉션으로 조각을 되돌려서는 안 됩니다.

### ShapeKey 요약

<a id="mesh-shape-summary"></a>
#### 컬렉션 전체에서 같은 이름의 ShapeKey 제어

이름이 같은 ShapeKey를 한 목록에 모아 여러 오브젝트로 구성된 의상을 함께 조절합니다.

**위치:** Mesh Tools → ShapeKey Summary (by Collection).

##### 절차
1. 관련 메시가 들어 있는 컬렉션을 선택합니다.
2. 목록이 스캔되도록 기다리거나 구조 변경 후 Force refresh를 클릭합니다.
3. 행의 값을 움직이면 해당 이름의 참여 키가 함께 바뀌고, 이름을 편집하면 참여 키들이 함께 이름을 바꿉니다.
4. **xN**에 마우스를 올리면 정확히 어느 오브젝트가 참여하는지 볼 수 있습니다.

##### 간단한 예
바디, 셔츠, 벨트에 모두 **FitWide**가 있습니다. 행은 x3으로 표시됩니다. 공유 슬라이더를 움직이면 세 오브젝트가 함께 바뀌어 벨트만 뒤처지지 않습니다.

##### 확인 및 복구
이 패널에서는 이름이 같으면 함께 제어됩니다. 독립적이어야 하는 키는 먼저 개별 오브젝트에서 이름을 바꾸세요. 번호가 있는 Deform 행이 먼저 정렬되고 이후 자연스러운 이름순을 따릅니다. 이 패널은 Blender 데이터를 정리하며 런타임 내보내기에는 여전히 [게임의 ShapeKey 옵션](#game-efmi-shapes)이 필요합니다.

<a id="mesh-shape-number"></a>
#### 커스텀 ShapeKey에 안전한 Deform 번호 부여

선택한 아직 번호가 없는 항목에 런타임용 번호를 붙입니다. 이미 번호가 있는 항목은 보호하며 사용 가능한 가장 작은 유효 번호를 사용합니다.

**위치:** ShapeKey Summary → 행 체크박스 → Automatically rename.

##### 절차
1. 올바른 게임을 설정합니다. WWMI라면 먼저 유효한 Metadata.json이 있는 현재 오브젝트 소스를 설정합니다.
2. 컬렉션 목록을 새로고침합니다. 번호를 붙일 항목을 체크합니다. Select All/Select None은 이름 변경 가능한 항목에만 적용됩니다.
3. Automatically rename을 실행합니다.
4. 결과 이름을 확인하고 해당 게임의 커스텀 ShapeKey 내보내기를 켭니다.

##### 간단한 예
EFMI 프로젝트에 Deform 1과 Deform 8이 이미 있습니다. **CapeLift**를 선택하면 불필요하게 9부터 시작하지 않고 **Deform 2 CapeLift**가 될 수 있습니다. WWMI는 기본 범위도 예약하므로 다음 사용 가능 번호가 훨씬 클 수 있습니다.

##### 확인 및 복구
체크박스는 이름 변경 대상 선택용이며 가시성이나 내보내기 토글이 아닙니다. 예전 도움말에 ‘unchecked’가 있더라도 여기 설명한 체크박스/작업 동작을 따르세요. WWMI 메타데이터가 없거나 잘못되면 기본 ID와 충돌할 위험을 감수하지 않고 번호 부여를 취소합니다. EFMI 예제 번호를 WWMI 프로젝트에 그대로 쓰지 마세요.


<a id="weights"></a>
## 웨이트 도구 (Weight Tools)

웨이트는 영향력의 크기입니다. 0은 영향 없음, 1은 해당 그룹의 완전한 영향을 뜻합니다. 잘 정리된 최종 정점은 보통 총합과 영향 본 수가 관리되어 있지만, Velo는 복사와 정리를 의도적으로 분리합니다. 먼저 전송하고 어떤 값을 바꿔도 되는지 결정한 뒤 정규화하세요.

### 작업 오브젝트 및 전송

<a id="weight-objects"></a>
#### 소스·수신 대상·선택적 미러 지정

소스는 한 그룹의 영향력 분포를 제공하고 대상은 이를 받습니다. 명시적인 필드를 설정한 뒤에는 마지막으로 클릭한 오브젝트를 암묵적으로 사용하지 않습니다.

**위치:** Weight Tools → Working Objects.

##### 절차
1. Source Mesh에 올바르게 웨이트가 설정된 참조를 지정합니다. Source Vertex Group을 선택하고 그룹 목록 변경 후에는 새로고침 아이콘을 사용합니다.
2. Target Mesh에 웨이트를 받을 의상 또는 교체 메시를 지정합니다.
3. Mirror Vertex Group을 확인합니다. 반대쪽 그룹을 지정하거나 한쪽만 전송하려면 비웁니다.
4. 없는 수신 본을 생성해야 한다면 Target Skeleton을 지정합니다. 실제 소스와 대상 표면을 정렬합니다.

##### 간단한 예
소매에 웨이트를 주려면 소스는 참조 팔, 소스 그룹은 위팔의 영향력, 대상은 소매입니다. 소매가 뷰포트에서 선택되었다고 소스가 되는 것은 아닙니다.

##### 확인 및 복구
잠긴 그룹과 특수 그룹은 소스 후보에서 제외됩니다. 정확한 이름의 오브젝트 필드는 대상이 없어지면 이름을 빨간색으로 유지하고 같은 이름의 메시가 돌아오면 다시 연결됩니다. X로 비울 수 있습니다. 병합 후 대상 필드가 계속 빨간색이면 실제 새 이름을 지정해야 할 수 있습니다. 비슷한 이름을 추측하지 않습니다.

<a id="weight-engine"></a>
#### Robust 또는 표면 보간 선택

두 엔진은 모두 소스 표면을 샘플링하지만 빈 영역을 다르게 처리합니다. Robust는 직접 표면 매칭이 없는 영역까지 유효한 샘플을 확장하는 인페인팅을 추가합니다.

**위치:** Weight Tools → Transfer settings → Transfer engine.

##### 절차
1. 틈이 있거나 겹침이 고르지 않은 의상에는 Robust를 시도합니다.
2. Install Robust dependencies가 표시되면 용량을 확인하고 먼저 설치합니다. 완료될 때까지 기다립니다.
3. Blender 내장 최근접 면 보간 경로가 적합하다면 Face interpolation pass를 선택합니다.
4. 전체 의상을 처리하기 전에 저장한 사본에서 수신 그룹 하나를 테스트합니다.

##### 간단한 예
몸에 붙는 소매는 일반 표면 보간에 적합합니다. 느슨한 커프스가 있는 소매는 빈 영역을 안내할 신뢰할 만한 주변 샘플이 충분하다면 Robust가 도움이 될 수 있습니다.

##### 확인 및 복구
함께 제공되는 선택적 네이티브 패키지 매니페스트는 Windows CPython 3.11용입니다. 다른 Blender/Python 환경까지 자동 지원하지는 않습니다. 패키지는 애드온 외부에 설치되며 별도의 Robust 애드온은 필요하지 않습니다. 설치나 매칭 실패 시 전체 보고서를 확인하세요. 엔진 변경으로 잘못된 본 매핑이나 모델 정렬을 고칠 수는 없습니다.

<a id="weight-transfer"></a>
#### 다른 그룹을 몰래 바꾸지 않고 한 그룹 전송

샘플링한 수신 분포와 선택적 엄격 미러를 복사합니다. 임시 총합이 1보다 크거나 작아져도 무관한 기존 그룹은 값을 유지합니다.

**위치:** Weight Tools → Transfer settings → Execute weight transfer.

##### 절차
1. [Working Objects](#weight-objects)를 설정합니다. 수신 이름 수동 지정이 꺼져 있다면 MMD 매핑에서 추론한 그룹을 확인합니다.
2. 명시적으로 덮어쓸 때만 Manually specify receiving group을 켭니다. 미러 수신 그룹도 확인합니다.
3. 교체할 수신 그룹의 잠금을 해제합니다. 재사용/초기화 동작은 고정되어 있어 기존의 잠기지 않은 수신 그룹을 재사용하고 이전 분포를 교체합니다.
4. 선택적으로 스무딩을 설정하고 전송합니다. Auto-lock receiving groups로 완료된 기록을 보호할 수 있습니다.
5. 다른 그룹에도 반복한 뒤 [수동 정리](#weight-normalize)를 수행합니다.

##### 간단한 예
정점에 무관한 웨이트 0.8이 있고 새 수신 샘플이 0.6이라면 둘 다 유지해 총합은 1.4가 됩니다. 0.6을 0.2로 줄이지 않습니다. 어떤 그룹의 크기를 조정할지는 나중에 결정합니다.

##### 확인 및 복구
도너와 그룹 개수 제한은 소스 전송을 제약하지 않습니다. 미러 대응이 없거나 모호하면 보고하고 레이어를 평균내는 대신 목적지를 보존합니다. 검증된 기록에 실패하면 그룹 소속과 잠금을 되돌립니다. Blender 본을 만든다고 지원되는 새 게임 런타임 본이 생성되는 것은 아닙니다.

<a id="weight-smooth"></a>
#### 복사한 분포에 필요할 때만 스무딩

선택적 스무딩은 최종 미러를 만들기 전에 새 수신 그룹의 급격한 변화를 완화합니다. 메시 전체의 자동 정리는 아닙니다.

**위치:** Weight Tools → Post-processing → Enable smoothing, 반복 횟수 및 강도.

##### 절차
1. 엔진의 실제 샘플 결과를 보려면 스무딩을 끄고 시작합니다.
2. 변화가 너무 급하면 낮은 강도와 적은 반복 횟수로 켭니다.
3. 이전 전송에서 자동 잠긴 수신 그룹은 다시 전송하기 전에 잠금을 해제합니다.
4. 전송 후 관절 굽힘과 경계 영역을 비교합니다.

##### 간단한 예
소매의 위팔 영향력이 팔꿈치 부근에서 급격히 끊깁니다. 사본에서 강도 **0.2**와 몇 회 반복을 시도하고 스무딩 없는 결과와 비교합니다. 모든 모델에 적용할 설정이 아니라 시험값입니다.

##### 확인 및 복구
반복이 많으면 유용한 세부 정보가 흐려질 수 있습니다. UV 심 에지는 스무딩 전파를 막으므로 경계가 남을 수 있습니다. 다른 그룹을 정규화하지 않으며 체크박스만 켠다고 이미 복사한 웨이트가 고쳐지지 않습니다. 전송 작업에서 사용하는 옵션입니다.

### 미러 및 그룹 전송

<a id="weight-mirror"></a>
#### 명시적 쌍을 사용해 활성 그룹 미러링

Mirror Weight는 처리 가능한 Component 메시에서 전체 그룹을 대상으로 하는 독립 작업입니다. 아래의 선택 정점 복구 버튼과는 다릅니다.

**위치:** Weight Tools → Mirror Mapping Groups.

##### 절차
1. 게임의 내보내기 컬렉션을 설정하고 대상 Component 메시를 활성화합니다.
2. 기준이 될 활성 그룹을 선택하고 자동 좌우 감지를 검토합니다.
3. 이름이나 숫자가 신뢰할 만한 쌍을 나타내지 않으면 수동 쌍 행을 추가합니다. 불필요한 행은 빼기로 제거합니다.
4. Normalize standalone mirror와 영향 수 제한을 적용할지 결정하고 Mirror Weight를 실행합니다.

##### 간단한 예
이 소스에서 **12**와 **18**이 알려진 좌우 쌍입니다. 쌍을 기록하고 정상인 쪽을 활성화한 뒤 미러링합니다. 확인 없이 다른 소스에 이 예제 번호를 쓰지 마세요.

##### 확인 및 복구
독립 미러 정규화는 잠긴 그룹을 보존하고 처리 가능한 잠기지 않은 그룹으로 남은 여유를 분배합니다. 자동 도너 수는 선호 설정이며 허용되는 그룹을 그것들로만 한정하는 목록이 아닙니다. 손상된 점 몇 개만 정확히 복사하려면 정규화하지 않는 [선택 정점 미러](#weight-selected-mirror)를 사용하세요.

<a id="weight-group-move"></a>
#### 같은 메시에서 한 그룹의 웨이트를 다른 그룹으로 이동

소스 그룹 값을 대상에 더한 뒤 소스 값을 비웁니다. 다른 메시를 샘플링하거나 이름만 바꾸는 기능이 아닙니다.

**위치:** Weight Tools → Weight Group Transfer.

##### 절차
1. 대상 메시를 활성화합니다.
2. 왼쪽 Source Group과 오른쪽의 다른 기존 Target 그룹을 선택합니다.
3. 바꿀 그룹들이 잠금으로 보호되지 않았는지 확인합니다.
4. Execute weight group transfer를 실행하고 전체 결과를 확인합니다.

##### 간단한 예
정점의 불필요한 보조 그룹에 0.2, 의도한 부모 그룹에 0.5가 있다면 전송 후 부모는 0.7이 되고 보조 그룹의 해당 정점 할당은 없어집니다.

##### 확인 및 복구
1을 넘는 값은 기록할 때 잘리고 보고됩니다. 합이 1을 넘으면 무손실 작업이 아닙니다. 소스 그룹 이름은 빈 상태로 남을 수 있습니다. 방향이 잘못되었다면 실행 취소하고, 비어 있는 그룹을 제거하기 전에 관절을 테스트하세요.

<a id="weight-map-merge"></a>
#### 동일 대상을 공유하는 여러 매핑 소스 통합

여러 소스 그룹이 실제로 하나의 목적지를 의미한다면 적절한 부모 소스로 웨이트를 합치고 중복 대응을 제거합니다. 소스 웨이트와 테이블 행이 모두 바뀝니다.

**위치:** Weight Group Transfer → merge according to MMD mapping / general mapping.

##### 절차
1. blend를 저장하고 관련 매핑 테이블의 백업을 내보냅니다.
2. 같은 대상을 가리키는 모든 행과 소스 아마추어 계층을 검토합니다.
3. 실제로 설정한 MMD 또는 General 테이블에 맞는 작업을 선택합니다.
4. 유지된 부모 그룹, 비워지거나 제거된 소스 그룹, 연결 해제되거나 정리된 행을 확인합니다.

##### 간단한 예
소매의 두 보조 영향력이 의도적으로 게임의 한 위팔 식별자에 매핑됩니다. 통합하면 이름 변경 목적지를 놓고 경쟁하는 두 그룹 대신 선택된 계통의 부모 아래 합쳐진 영향력이 남습니다.

##### 확인 및 복구
임의의 활성 메시가 아니라 해당 테이블에 설정된 소스에 작용합니다. 잘못된 다대일 매핑은 수정해야 하며 합쳐서 정당화해서는 안 됩니다. 변형과 내보내기를 확인할 때까지 백업을 보관하세요.

### 정리 및 국소 복구

<a id="weight-normalize"></a>
#### 선택 정점 정규화 및 영향 수 제한

선택적으로 영향력을 정리한 뒤 편집 가능한 기존 웨이트를 비례 재분배합니다. 잠긴 그룹은 값을 유지하며 없는 그룹 소속을 새로 만들지 않습니다.

**위치:** Weight Tools → Post-processing → Normalize selected vertices by proportion.

##### 절차
1. 원하는 전송을 끝내고 대상 메시의 Edit Mode로 들어갑니다.
2. 정리할 정점만 선택합니다.
3. 값을 바꿔도 되는 그룹의 잠금을 명시적으로 해제합니다. 대상 레이아웃에 필요하다면 Limit the number of vertex groups와 최대 개수를 설정합니다.
4. 정규화를 실행하고 정점별 총합, 영향 개수, 변형을 확인합니다.

##### 간단한 예
보호된 그룹은 0.6으로 잠겨 있고 편집 가능한 두 기존 그룹은 0.3과 0.1입니다. 이미 남은 0.4에 맞습니다. 편집 가능 값이 0.6과 0.2였다면 잠긴 값은 유지하면서 비례 정리로 0.3과 0.1로 되돌릴 수 있습니다.

##### 확인 및 복구
흔한 기본값인 영향 4개는 모든 게임의 규칙이 아닙니다. 잠긴 웨이트만으로 허용 총량을 맞출 수 없다면 수동 검토가 필요합니다. 완료 그룹을 몰래 잠금 해제하지 않습니다. 정규화는 잘못 샘플링한 본을 고치거나 잘못된 스무딩을 되돌릴 수 없습니다.

<a id="weight-selected-mirror"></a>
#### 선택한 미러 정점만 복구

메시의 로컬 X축을 가로질러 정상 쪽의 웨이트를 복사합니다. 정규화, 영향 수 제한, 지오메트리 편집 없이 목적지만 바뀝니다.

**위치:** Weight Tools → Post-processing → -X to +X / +X to -X → Mirror selected vertex weights.

##### 절차
1. 필요하면 공유 메시 데이터를 단일 사용자로 만든 뒤 Edit Mode로 들어갑니다.
2. 정상 쪽 끝점 또는 손상된 목적지 점만 선택합니다. 양쪽 모두 선택할 필요는 없습니다.
3. 화면 좌우가 아니라 로컬 X를 기준으로 방향을 선택합니다. 원하는 각 쌍의 두 그룹 모두 잠금을 해제합니다.
4. 실행합니다. F9로 방향을 조정하고 Ctrl+Z로 취소할 수 있습니다.

##### 간단한 예
양의 X쪽 커프스 손목 웨이트가 잘못되었습니다. 손상된 점만 선택하고 **-X to +X**를 고릅니다. 선택하지 않았더라도 음의 X쪽 커프스가 소스입니다.

##### 확인 및 복구
기존의 상호 대응 쌍만 참여하며 중립 그룹은 같은 이름으로 복사합니다. 식별하지 못한 숫자, 누락된 쌍, 모호하게 겹친 레이어는 건너뜁니다. 잠긴 그룹, 소스 값, 다른 정점, 선택 상태, ShapeKey는 유지됩니다. 보호 그룹 때문에 총합이 달라도 ‘고치지’ 않고 보호합니다.

<a id="weight-advanced"></a>
#### 무작정 조절하지 말고 전송 실패 진단

고급 설정은 어떤 표면 샘플을 받아들일지 제어합니다. 먼저 보고서를 읽고 실패와 관련된 매개변수를 바꾸세요.

**위치:** Weight Tools → Advanced; 클릭 가능한 마지막 결과 텍스트 및 복사 아이콘.

##### 절차
1. View full results를 엽니다. 오브젝트 이름, 수신 그룹 잠금, 누락된 매핑, 의존성 오류부터 확인합니다.
2. Robust 거리 실패라면 Maximum Distance를 바꾸기 전에 실제 모델 크기와 정렬을 확인합니다.
3. 얇거나 반대 방향을 보는 표면은 Normal Angle과 Allow normal flipping을 검토합니다.
4. 최종 계산 형태를 의도할 때만 변형된 소스/대상을 사용합니다. 계산된 대상 토폴로지는 여전히 원본과 일치해야 합니다.

##### 간단한 예
오브젝트 위치가 잘못되어 커프스가 소스 손목에서 멀리 떨어져 있습니다. 정렬하는 것이 해결책입니다. 커프스가 몸통을 샘플링할 때까지 거리를 늘리면 실제 문제를 숨길 뿐입니다.

##### 확인 및 복구
Point inpaint는 인페인팅의 이웃 모델을 바꾸며 본 식별자를 바꾸지 않습니다. Limit dilation은 영향력 정리 중 보호에 관한 것이며 소스 전송 한도가 아닙니다. 진단을 위해 전체 보고서를 복사하고 프로젝트를 보존하세요. 짧은 ‘완료’ 메시지가 변형 검증을 대신하지는 않습니다.


<a id="materials"></a>
## 머티리얼 도구 (Material Tools)

항상 두 이미지를 구분하세요. **원본(original)**은 교체하려는 게임의 추출 텍스처이고 **교체 이미지(replacement)**는 직접 만든 이미지입니다. Blender에 보기 좋은 이미지를 연결하는 것만으로 올바른 게임 텍스처를 식별할 수는 없습니다. 이 탭은 셰이더 슬롯 번호를 직접 입력하지 않고 둘을 연결합니다.

### 먼저 작동하는 머티리얼 하나 만들기

<a id="material-start"></a>
#### 첫 머티리얼 전체 과정: 소매 텍스처 교체

의상 전체를 일괄 처리하기 전에 머티리얼 하나로 전체 경로가 작동하는지 확인합니다. 이 튜토리얼은 초보자에게 필요한 순서대로 개별 작업을 연결합니다.

**위치:** Material Tools, 이후 Game → 선택한 게임의 Export Mod.

##### 절차
1. 일반적인 단일 소스 EFMI 또는 WWMI 프로젝트를 준비하고 사본을 저장합니다. 추출한 원본 텍스처는 오브젝트 소스 폴더에 둡니다.
2. 소매와 의도한 활성 머티리얼을 선택하고 [초기화](#material-initialize)합니다.
3. 의미별 입력에 저장된 교체 디퓨즈와 노멀을 연결하고 [각 원본을 확인](#material-original)합니다.
4. Export Mod에서 Auto Split by Material, Slot-style Textures, Use Material Textures를 켭니다. 기본 템플릿, 전체 INI 출력, 텍스처 복사를 유지합니다.
5. 별도 테스트 출력으로 내보내고 게임에서 결과를 확인한 뒤 더 많은 머티리얼로 [전파](#material-propagate)합니다.

##### 간단한 예
**Sleeve_D.dds**는 새 색상 이미지이고 **Sleeve_N.dds**는 새 노멀입니다. 각 역할은 소매 Component의 올바른 추출 원본을 가리킵니다. 원본 선택기에 Sleeve_N을 넣거나 추측한 ps-t 번호를 입력하지 않습니다.

##### 확인 및 복구
현재 독립 머티리얼 레이어는 CrossIB, WWMI Cross-Scene, 에셋 이름 매칭, 커스텀/라이브 템플릿, 부분 내보내기를 지원하지 않습니다. 일반 Slot 내보내기가 특정 작업을 지원한다고 이 추가 레이어도 지원하는 것은 아닙니다.

<a id="material-initialize"></a>
#### 선택 머티리얼 안전하게 초기화

식별 가능한 디퓨즈 이미지와 UV 연결을 유지하면서 플러그인의 의미별 텍스처 입력 셰이더를 생성합니다. 원래 머티리얼은 백업으로 남습니다. 임의의 모든 셰이더 효과를 보존하는 변환은 아닙니다.

**위치:** Material Tools → Initialize Selected Materials.

##### 절차
1. 올바른 게임과 오브젝트 소스를 선택합니다. 소스 없이도 초기화할 수 있지만 나중에 원본 매핑을 확인해야 합니다.
2. Object Mode에서 사용하는 머티리얼을 초기화할 메시만 선택합니다.
3. Initialize Selected Materials를 실행합니다.
4. Shader Editor에서 의미별 입력 노드의 Shader 출력이 활성 Material Output에 도달하는지 확인합니다.

##### 간단한 예
가져온 MMD 소매에 식별 가능한 디퓨즈가 있지만 미리보기 셰이더가 복잡합니다. 초기화하면 디퓨즈의 벡터 경로를 보존하면서 명확한 Diffuse/Normal 등의 입력을 제공합니다. 특수 미리보기 효과는 별도로 확인하세요.

##### 확인 및 복구
선택하지 않은 사용 오브젝트의 머티리얼 내용과 슬롯 할당은 유지됩니다. 편집한 교체 머티리얼이 이름을 우선 사용하며 원본은 원하는 이름을 차지하는 대신 **Backup <name>**이 될 수 있습니다. 이미 초기화한 머티리얼을 다시 초기화하면 연결을 다시 만들지 않고 갱신합니다. 실행 취소하거나 보존한 원본을 재할당해 되돌립니다.

<a id="material-inputs"></a>
#### 각 의미별 입력에 올바른 이미지 연결

의미별 입력은 이미지의 역할을 나타냅니다. 이미지를 자동으로 그 종류의 맵으로 변환하지 않습니다. Blender 미리보기는 게임 셰이더의 근사 표현일 뿐입니다.

**위치:** Shader Editor → 초기화된 머티리얼의 텍스처 입력 노드.

##### 절차
1. 저장한 각 이미지에 대해 Image Texture를 추가하거나 엽니다.
2. **Color 출력**을 직접 또는 reroute를 거쳐 적절한 의미별 입력에 연결합니다.
3. Shader와 활성 Material Output의 연결을 유지합니다.
4. 내보내기 전에 칠하거나 편집한 이미지를 저장합니다. 프로시저럴 결과는 먼저 지원 파일로 베이크합니다.

| 입력 | 용도 |
| --- | --- |
| Diffuse | 기본 표면 색상 |
| Normal | 미세한 표면 방향. 두 번째 색상 이미지가 아닙니다. |
| Packed PBR (Endfield) | 여러 머티리얼 속성을 하나의 이미지에 저장 |
| FTM (WWMI) | 게임의 패킹된 머티리얼 제어 이미지 |
| Mask | 원본 셰이더에 따라 의미가 달라지는 제어 이미지 |
| Emission | 발광 표현용 이미지 |
| Light Map / Detail | 소스가 실제로 사용할 때의 추가 셰이딩/디테일 이미지 |

##### 간단한 예
Sleeve_D의 Color를 Diffuse에, Sleeve_N의 Color를 Normal에 연결합니다. 프로시저럴 혼합을 끼워 넣고 익스포터가 이를 재구성하리라 기대하지 마세요. Alpha는 미리보기 제어용이며 별도로 내보내는 텍스처 역할이 아닙니다.

##### 확인 및 복구
Packed PBR/FTM 바이트는 변경 없이 복사합니다. 알 수 없는 게임 맵의 채널이 일반적인 metallic/roughness 의미일 것으로 가정하지 마세요. 저장된 DDS/PNG/JPG/JPEG/TGA/BMP와 파일에서 패킹한 이미지는 변환 없이 지원합니다. 저장하지 않은 변경 이미지, 생성형, 애니메이션, 타일 또는 프로시저럴 이미지는 먼저 저장/베이크해야 합니다.

### 원본 대응

<a id="material-original"></a>
#### 각 역할이 교체할 게임 원본 텍스처 선택

선택기는 새 이미지가 아니라 기존 텍스처를 식별합니다. 제안이 유일하면 즉시 적용하고 후보가 실제로 모호하면 선택할 때까지 미할당으로 둡니다.

**위치:** Material Tools → 활성 머티리얼의 역할 → Choose Original Texture.

##### 절차
1. 일치하는 게임 오브젝트 소스 폴더를 설정하고 소스 매핑을 새로고침합니다.
2. 연결된 각 역할 아래에 표시되는 원본 파일명을 확인합니다.
3. 잘못되었거나 미할당인 역할을 클릭하고 교체하려는 추출 원본을 고릅니다.
4. 의도적으로 교체하지 않을 항목은 Keep Game Texture로 둡니다. 내보내기 전에 연결되고 활성화된 모든 역할을 검증합니다.

##### 간단한 예
소매에서 주 표면과 별도 디테일 패스의 노멀처럼 보이는 이미지 두 개가 추출되었습니다. 보존한 참조/근거를 사용해 Sleeve_N에 맞는 주 노멀을 고릅니다. 형식이나 색상이 비슷하다는 것만으로는 부족합니다.

##### 확인 및 복구
후보 힌트는 캡처된 사용 정보, 형식, 크기, 이름을 사용합니다. 제안일 뿐 범용 셰이더 슬롯 규칙은 아닙니다. 수동 선택이 우선하며 각 Component는 자체 원본과 런타임 목적지를 해석합니다. 미해결 역할이 빨간색이라고 색을 없애려고 첫 항목을 선택해서는 안 됩니다.

<a id="material-refresh"></a>
#### 머티리얼을 다시 만들지 않고 원본 갱신

직접 만든 이미지 연결과 수동 선택을 유지하면서 현재 추출 소스 목록을 다시 읽습니다. 최상위에 보존한 파일이 현재 사용 가능한 원본을 결정합니다.

**위치:** Material Tools → Refresh Source Mapping.

##### 절차
1. Mod 출력 폴더가 아니라 올바른 오브젝트 소스 폴더인지 확인합니다.
2. 원하는 원본 이미지는 폴더 바로 아래에 둡니다. 의도적으로 제외할 원본은 추출 JSON을 고치지 말고 백업 하위 폴더로 옮깁니다.
3. 활성 머티리얼에서 Refresh Source Mapping을 실행합니다.
4. 새롭게 유일하게 할당된 항목, 유지된 수동 선택, Keep Game Texture로 표시된 역할을 확인합니다.

##### 간단한 예
이전에 매핑한 공유 마스크에 더 이상 추가 교체를 적용하지 않으려 합니다. 보존된 원본을 소스 루트 밖으로 옮기고 새로고침합니다. Blender 노드는 미리보기용으로 남지만 제거한 원본은 자동 교체되지 않습니다. 파일을 다시 놓으면 추론 매핑이 복구될 수 있습니다.

##### 확인 및 복구
명시적으로 선택한 Keep Game Texture는 계속 제외 상태를 유지합니다. 새로고침은 새 PNG를 게임으로 복사하는 버튼이 아닙니다. 전파된 기존 매핑은 갱신 후에도 유지됩니다. 반복 편집 시에도 .001 접미사를 계속 쌓기보다 편집한 머티리얼 이름을 유지합니다.

### 전파 및 지속적 동기화

<a id="material-propagate"></a>
#### 한 번 설정한 뒤 같은 디퓨즈를 기준으로 전파

동일한 디퓨즈 이미지를 사용하는 선택 머티리얼에 다른 텍스처 역할을 복사합니다. 동일함은 같은 이미지 식별자 또는 정규화된 저장 경로를 뜻하며 단순히 비슷해 보이는 이미지가 아닙니다.

**위치:** Material Tools → Propagate by Same Diffuse.

##### 절차
1. 소스 머티리얼 하나를 완전히 설정합니다. 해당 머티리얼을 활성화한 상태로 소스와 대상 메시를 선택합니다.
2. 대상이 같은 디퓨즈를 쓰는지 확인합니다. 선택한 모든 머티리얼 슬롯이 원본 식별 근거를 제공할 수 있지만 변경되는 대상은 실제 면에서 사용되어야 합니다.
3. Replace Existing Connections를 끄고 전파하여 빈 입력을 채웁니다.
4. 연결/초기화/매핑 수와 미해결 역할을 확인합니다. 대상의 이미 채워진 비디퓨즈 역할도 바꿀 때만 덮어쓰기를 켭니다.

##### 간단한 예
소매 머티리얼 다섯 개가 하나의 디퓨즈를 사용합니다. 하나에 노멀과 발광을 설정하고 모두 선택해 전파합니다. 빈 입력만 채우는 모드에서는 독립적으로 편집된 대상 노멀은 유지되고 비어 있는 발광은 채워질 수 있습니다. 각 Component는 여전히 자체 원본 매핑을 받습니다.

##### 확인 및 복구
설정된 활성 머티리얼이 우선입니다. 그것이 없다면 선택된 설정 완료 소스가 정확히 하나여야 합니다. 덮어쓰기 모드는 소스에 없는 비디퓨즈 역할도 지웁니다. 빈 입력만 채우는 모드에서도 이전에 연결된 소스에서 역할을 제거하면 선택된 여전히 연결된 멤버에 전파됩니다. 독립적으로 변경해 채워진 역할에는 적용하지 않습니다. 빈 이미지 노드와 끊어진 reroute는 유효 이미지로 내보내지 않고 연결을 해제합니다.

<a id="material-replace"></a>
#### 동기화된 멤버 어디에서나 텍스처 교체

전파는 역할별 멤버 관계를 명시적으로 기록합니다. 이후 교체는 이 멤버를 사용하며 비슷해 보이는 모든 머티리얼을 전역 검색하지 않습니다.

**위치:** Material Tools → 역할의 교체 경로 행 → 폴더 아이콘; Synced: N materials.

##### 절차
1. Synced: N materials를 클릭해 해당 역할에 속한 정확한 오브젝트/머티리얼 사용처를 확인합니다.
2. 교체 경로 옆 폴더 아이콘을 클릭하고 새로 저장한 이미지를 고릅니다.
3. 뷰포트에서 선택하지 않은 멤버를 포함해 목록의 모든 멤버를 확인합니다.
4. blend를 저장합니다. 다시 열거나 일반적으로 오브젝트/머티리얼/이미지 이름을 바꿔도 멤버 관계가 유지됩니다.

##### 간단한 예
소매 노멀을 다섯 머티리얼에 전파한 뒤 멤버 하나만 선택해 **Sleeve_N_v2.dds**로 교체합니다. 여전히 연결된 다섯 노멀 역할이 모두 갱신됩니다. 게임 원본 식별자와 UV 연결은 각자의 것을 유지합니다.

##### 확인 및 복구
경로 필드는 읽기 전용 정보이며 원본 선택기가 아닙니다. 패킹 파일은 기록된 경로를 표시하며 외부에 실제 파일이 없어도 됩니다. 공유 Image 데이터블록의 경로를 전역 변경하는 대신 노드 이미지를 교체합니다. 복제 오브젝트는 자동으로 멤버에 추가되지 않습니다. 수동 노드 편집은 의도적으로 다시 전파할 때까지 독립 상태가 됩니다.

<a id="material-independent"></a>
#### 역할 하나의 동기화 해제, 매핑 지우기, 게임 텍스처 유지

세 기능은 서로 다른 문제를 해결합니다. 어느 것도 ‘연결된 모든 이미지 삭제’ 버튼이 아닙니다.

**위치:** Material Tools → 각 역할의 연결 해제, 원본 초기화, 원본 선택기.

##### 절차
1. 독립 편집, 새 원본 할당, 추가 내보내기 교체 없음 중 원하는 결과를 결정합니다.
2. 아래에서 맞는 작업을 사용합니다.
3. 교체 경로, 원본 상태, 멤버 수를 각각 확인합니다.
4. 세 상태가 의도와 맞을 때만 새로고침/내보내기를 합니다.

| 작업 | 원본 식별자 | 이미지 연결 | 동기화 |
| --- | --- | --- | --- |
| Leave This Texture Sync | 유지 | 유지 | 이 오브젝트/머티리얼의 해당 역할만 이탈 |
| Clear Original Mapping | 미할당. 수동 제외도 지움 | 유지 | 유지 |
| Keep Game Texture | 이 추가 교체를 명시적으로 건너뜀 | 미리보기용으로 유지 | 유지. 교체해도 내보내기를 다시 켜지 않음 |

##### 간단한 예
커프스 하나에 다른 노멀이 필요하면 해당 노멀의 동기화를 해제하고 교체합니다. 게임 노멀을 그대로 쓰려면 Keep Game Texture를 선택합니다. 원본 지우기는 영구 비활성화가 아닙니다. 새로고침 시 다시 추론할 수 있습니다.

##### 확인 및 복구
다른 역할과 멤버는 계속 연결됩니다. Keep Game Texture는 이 머티리얼 레이어만 건너뛰며 다른 기존 Component/Hash 오버라이드를 제거하지 않습니다. 실수는 실행 취소로 되돌리고 그룹을 편집하기 전에 실제 범위를 확인하세요.

### 내보내기 및 검증

<a id="material-export"></a>
#### 독립 머티리얼 텍스처 내보내기 활성화

이 추가 내보내기 레이어는 서로 다른 머티리얼 드로우가 같은 원본을 서로 다른 이미지로 교체할 수 있게 합니다. Component와 패스를 인식하는 안전한 Slot 근거가 필요합니다.

**위치:** Game → EFMI/WWMI → Export Mod → Velo Compatibility Options.

##### 절차
1. 현재 ShaderTextureUsage.json이 있는 일반 단일 소스 프로젝트를 사용합니다.
2. Auto Split by Material, Slot-style Textures, Use Material Textures를 켭니다.
3. 호환되는 런타임에서 Native Format Read를 선택하거나 의도적으로 이전 방식인 Fuzzy를 선택합니다. 전체 내보내기, 기본 템플릿, INI 기록, 텍스처 복사를 유지합니다.
4. 연결된 역할을 해결한 뒤 내보냅니다. 생성 파일을 확인하고 게임에서 두 파트를 비교합니다.

##### 간단한 예
소매와 커프스가 같은 게임 원본 디퓨즈를 공유하지만 각각 파란색과 흰색 이미지가 필요합니다. 두 머티리얼을 독립 설정하면 각 드로우가 자기 교체 이미지를 받고 다른 파트의 원본 식별자는 바뀌지 않습니다.

##### 확인 및 복구
CrossIB, WWMI Cross-Scene, 에셋 이름 매칭, 커스텀/라이브 템플릿, Partial Export는 현재 제외됩니다. Auto Split을 끄면 머티리얼 레이어가 숨겨지고 우회되며 몰래 추론해 적용하지 않습니다. 초기화되지 않은 머티리얼은 이전 경로를 유지합니다. 익스포터가 대신 초기화하지 않습니다.

<a id="material-batching"></a>
#### 필요한 순서를 보존하며 텍스처별 드로우 그룹화

최종 인덱스 범위를 만들기 전에 전체 바인딩이 같은 호환 파트들을 이웃하게 배치해 반복 텍스처 설정을 줄입니다.

**위치:** Export compatibility → Group Draws by Texture; Material Tools → Preserve Draw Order.

##### 절차
1. 독립 머티리얼 텍스처를 켭니다. Group Draws by Texture는 기본적으로 켜집니다.
2. 게임에서 순서가 중요한 머티리얼에 Preserve Draw Order를 지정합니다.
3. 내보낸 뒤 원하는 투명도/레이어 겹침을 확인합니다.
4. 텍스처 할당이나 동기화를 끄지 않고 기존 오브젝트 순서와 비교하려면 그룹화를 끕니다.

##### 간단한 예
불투명 파트의 바인딩이 A/B/A/B라면 A/A/B/B로 묶어 이웃한 텍스처 설정을 공유할 수 있습니다. 사이에 보호된 투명 장식이 있으면 경계로 남으며 다른 파트가 이를 넘어 이동해서는 안 됩니다.

##### 확인 및 복구
그룹화는 Component 내부에서만 수행하고 오브젝트별 드로우 명령과 가시성을 유지합니다. 초기화되지 않은 경로, 비호환 경로, 기록된 투명/CPU 포즈 경로는 보호됩니다. Blender 미리보기의 Alpha 연결이나 BLENDED 설정만으로는 게임 블렌드 상태의 근거가 되지 않아 배칭을 자동으로 끄지 않습니다. 게임에서 필요함을 안다면 명시적인 순서 옵션을 사용하세요.

<a id="material-files"></a>
#### 파일명과 기존 출력 텍스처가 바뀌지 않는 이유

교체 이미지는 Textures 안에서 기록된 기본 파일명과 확장자를 유지합니다. 내보내기는 없는 파일을 추가하며 같은 이름의 기존 출력 이미지는 덮어쓰지 않습니다.

**위치:** Mod 출력 → Textures; 생성된 mod.ini 리소스의 filename 참조.

##### 절차
1. 내보내기 전에 각 교체 이미지를 명확한 파일명으로 저장합니다.
2. 서로 다른 소스 이미지가 Windows 기준으로 같은 목적지 기본 파일명을 갖지 않게 합니다.
3. 내보낸 뒤 mod.ini의 실제 filename 항목을 따라 확인합니다.
4. 이전에 배포한 텍스처를 갱신하려면 출력 파일을 직접 교체하거나 소스를 새 이름으로 저장하고 다시 내보냅니다.

##### 간단한 예
Textures에 지난 내보내기 이후 직접 칠한 **Sleeve_D.dds**가 이미 있습니다. 소스 Sleeve_D.dds의 바이트나 크기가 달라도 보존합니다. 다음 소스를 **Sleeve_D_v2.dds**로 저장하면 새 목적지를 만들고 생성되는 참조를 갱신합니다.

##### 확인 및 복구
출력 내용 비교, 자동 형식 변환, 이전 파일 정리를 의미하지 않습니다. 하나의 이름을 향하는 입력 소스 파일끼리 충돌하면 내보내기는 중단됩니다. 리소스 섹션 라벨은 확장자를 뺀 이름을 정리하고 충돌 접미사를 붙일 수 있지만 전달되는 파일명을 바꾸지는 않습니다. 저장되지 않았거나 지원하지 않는 이미지 상태는 먼저 저장해야 합니다. Blender 미리보기가 올바르다고 게임 내 최종 검증이 끝난 것은 아닙니다.


<a id="game"></a>
## 게임 (Game)

EFMI는 Arknights: Endfield(명일방주: 엔드필드), WWMI는 Wuthering Waves(명조)를 선택합니다. 일반적인 Extract → Import → Export 모드는 내장된 게임 도구에서 제공됩니다. Velo의 호환성 제어와 추가 패널은 그 흐름을 확장하며 서로 대체 가능한 지름길은 아닙니다.

### 여기서 시작

<a id="game-start"></a>
#### 설치·업데이트 및 프로젝트 시작

Velo는 Blender 측 도구입니다. 일치하는 게임 측 로더와 유효한 캡처도 필요합니다. 애드온 설치가 이들을 설치하거나 설정해 주지는 않습니다.

**위치:** Blender Preferences → Add-ons; 3D Viewport → N → Velo Tools.

##### 절차
1. GitHub의 자동 소스 압축 파일이 아니라 릴리스 에셋의 **velo_tools-1.7.1.zip**을 다운로드합니다.
2. Preferences → Add-ons에서 Install from Disk를 선택하고 zip을 지정한 뒤 Velo-Tools를 켭니다.
3. N으로 뷰포트 사이드바를 엽니다. Game에서 대상 게임을 고릅니다.
4. 해당 게임의 추출, 가져오기, 내보내기 튜토리얼을 따릅니다. 첫 테스트는 작게 시작합니다.

##### 간단한 예
첫 Endfield 프로젝트에서는 추출 원본을 가져오고 명확하지만 되돌릴 수 있는 메시 수정 하나를 한 뒤, 전체 의상을 교체하기 전에 테스트 사본을 내보냅니다.

##### 확인 및 복구
명시된 최소 버전은 Blender 3.6이며 주 테스트 환경은 4.4입니다. 선택적 Robust 의존성의 호환 범위는 더 좁습니다. Preferences의 Velo 호스트 업데이터로 업데이트하고 재시작하세요. 내장 EFMI/WWMI 코어를 따로 업데이트하지 마세요. 독립 도구와 함께 설치할 수 있습니다. 개발 소스 정션에서는 업데이터를 실행하지 마세요. 교체가 소스 저장소에 영향을 줍니다.

<a id="game-files"></a>
#### 다섯 작업 단계 구분

혼란스러운 가져오기/내보내기 오류는 대부분 잘못된 폴더에서 시작합니다. 소스 폴더는 게임 원본 데이터를 설명하고 출력 폴더는 새 Mod를 담습니다.

**위치:** Extract/Import/Export 폴더 필드.

##### 절차
1. 새 **Frame Dump**를 보존합니다. 캡처한 버퍼, 텍스처, 드로우 정보 및 보통 log.txt가 포함됩니다.
2. Component 파일, Metadata, 텍스처 근거를 담은 **오브젝트 소스**를 추출합니다.
3. WWMI 크로스 씬 작업일 때만 별도의 **병합 소스**를 생성합니다.
4. Blender의 **Component 컬렉션**으로 가져오고 blend를 저장합니다.
5. 별도의 **Mod 출력**으로 내보냅니다. 출력을 그 자체의 오브젝트 소스로 사용하지 마세요.

##### 간단한 예
같은 수준의 **Capture**, **Source**, 필요할 때 **MergedSource**, **ModOutput** 폴더를 사용합니다. 일반 작업은 MergedSource를 건너뜁니다. 크로스 씬 작업은 이전 하위 소스가 아니라 병합 루트에서 가져오고 이를 기준으로 내보냅니다.

##### 확인 및 복구
Metadata.json은 지오메트리와 본을, TextureUsage.json은 기본 이미지 사용을, ShaderTextureUsage.json은 캡처된 셰이더/슬롯 근거를 설명합니다. 본 이름 보조 파일, CrossIB.json, CrossSceneManifest.json은 각각을 생성한 소스와 함께 둡니다. JSON 필드를 만들어 내거나 이미지 픽셀로 게임 Hash를 도출하려 하지 말고 오래된 근거를 다시 생성하세요.

### Arknights: Endfield · 기본 EFMI 작업 흐름

<a id="game-efmi-extract"></a>
#### Endfield 오브젝트 소스 추출

캡처를 편집 가능한 Component 파일과 이후 내보내기에 필요한 근거로 변환합니다. 캐릭터 추출은 임의의 텍스처 폴더를 여는 것과 다릅니다.

**위치:** Game → Arknights: Endfield → Mode: Extract Frame Data.

##### 절차
1. Frame Dump Directory에 대상 오브젝트가 포함된 새 캡처를 지정합니다.
2. 출력 디렉터리를 선택합니다. 비워 두면 덤프 위치를 사용합니다.
3. [필터](#game-efmi-filters)를 검토합니다. 나중에 Slot을 쓸 계획이라면 Dirty Slot 필터를 켜 둡니다.
4. CrossIB를 계획한다면 Generate CrossIB.json을 켭니다. 즉시 확인하려면 Import after extraction을 켭니다.
5. 추출 후 보고서와 생성된 캐릭터 폴더를 확인합니다.

##### 간단한 예
원하는 주요 디테일이 보이는 상태로 캐릭터를 캡처·추출한 뒤 Component 파일과 Metadata.json이 있는 폴더를 찾습니다. 여러 캐릭터가 담긴 상위 폴더가 아니라 해당 캐릭터 폴더가 가져오기 소스입니다.

##### 확인 및 복구
Tolerate extraction errors는 실패 오브젝트를 건너뛸 수 있으므로 일부 성공을 완전한 소스로 보지 마세요. Velo는 편집용으로 조밀하게 정리된 그룹 ID와 로컬-런타임 본 매핑을 따로 저장합니다. 함께 보관하고 다른 오브젝트의 맵을 빌리기보다 오래된 소스를 다시 추출하세요.

<a id="game-efmi-filters"></a>
#### 필요한 파트를 제거하지 않으면서 추출 필터링

필터는 캡처 내용을 좁힙니다. 어떤 파트가 시각적으로 중요한지 판단하지 않으며 일부 필터는 최종 Component 번호를 바꿉니다.

**위치:** EFMI Extract Frame Data → 오브젝트/Component/텍스처 필터 및 Velo Compatibility Options.

##### 절차
1. 이전 추출물을 새 결과로 오인하지 않도록 새 출력 폴더에서 시작합니다.
2. 정적 오브젝트, 최소 Component/텍스처 수 또는 특정 리소스 Hash에는 오브젝트 필터를 사용합니다.
3. 번호 체계를 이해한 뒤에만 Component Keep/Skip 범위를 사용합니다. Skip이 Keep보다 우선합니다.
4. 실제 보존된 출력과 새 연속 Component 번호를 확인합니다.

| 옵션 | 확인할 효과 |
| --- | --- |
| Automatically skip LOD components | 선택적으로 사용. 최종 번호 부여 전 원시 PS 텍스처 바인딩이 없는 드로우를 제거 |
| Component Keep / Skip | 0,1,5-7 같은 입력 허용. 자동 LOD 필터 후 적용 |
| Resource Hash targeting | 켜져 있고 명시적 대상이 비어 있지 않으면 자동 LOD 필터를 우회 |
| Skip small textures / JPG | 유용한 이미지도 제거할 수 있음. 단순 정리 목적으로 켜지 말 것 |
| Skip Dirty Slots | 사용 가능한 캡처 로그 근거가 있을 때만 오래된 상속 바인딩 제거 |

##### 간단한 예
Keep **0-8**, Skip **4,6**이면 LOD 필터 후 인덱스 0-3,5,7-8을 남기고 결과의 번호를 다시 매깁니다. 이전 Component 7에 맞춰 이름 붙인 교체 메시는 새 소스와 대조해야 할 수 있습니다.

##### 확인 및 복구
사용 가능한 로그 근거가 없으면 Dirty Slot 필터는 삭제를 추측하지 않고 이전 방식의 출력을 보존합니다. 원본 누락은 추출 단계에서 조사해야 합니다. 교체 이미지를 무관한 이미지에 할당해 ‘고치지’ 마세요.

<a id="game-efmi-import"></a>
#### Endfield Component 가져오기

추출 모델을 가져오고 그룹 식별자를 Component 간 공유할지 각 파트의 로컬 식별자로 유지할지 고릅니다.

**위치:** EFMI → Mode: Import Object.

##### 절차
1. Object Source Directory에 추출한 캐릭터 폴더를 지정합니다.
2. 버텍스 색상 저장 방식과 Merged 또는 Per-Component 가져오기를 선택합니다.
3. 필요하면 Component 하위 컬렉션을 켭니다. C0, C1 등을 만듭니다.
4. 소스 미리보기를 위해 Import Textures를 켜 둡니다. Mirror Mesh는 원하는 방향과 일치시킵니다.
5. 가져온 뒤 지오메트리, 그룹, 머티리얼, 컬렉션 구조를 확인합니다.

##### 간단한 예
공유 편집용 그룹 식별자로 전체 의상을 편집하려면 Merged를 고릅니다. 각 파트의 로컬 번호로 의도적으로 작업하려면 Per-Component를 선택합니다.

##### 확인 및 복구
Merged에는 적절한 Metadata v4 매핑이 필요합니다. 본 이름을 사용해 가져오려면 먼저 [본 이름 보조 파일](#game-efmi-names)을 생성하고 호환성 옵션의 Import bone-name mapping and skeleton을 켭니다. 기본값은 꺼짐입니다. 하위 컬렉션으로 가져왔다면 중첩 컬렉션 내보내기도 활성 상태여야 합니다.

<a id="game-efmi-names"></a>
#### Endfield 이름 있는 스켈레톤 생성

일치하는 언팩 LOD0 에셋을 사용해 Merged EFMI 프로젝트에 원본 본 이름과 방향이 설정된 계층을 가져옵니다.

**위치:** Game → Endfield → Named Bone Mapping; Import Object 호환성 옵션.

##### 절차
1. 일치하는 EFMI 오브젝트 소스를 설정합니다.
2. LOD0 GLB 또는 Avatar 하나와 원시 Unity YAML LOD0 Mesh/prefab 에셋을 포함하는 지원 언팩 캐릭터 루트를 선택합니다.
3. Generate Bone Name Mapping을 실행합니다. **BoneNameMapping.json**과 **BoneNameSkeleton.glb**를 소스와 함께 둡니다.
4. Merged 가져오기를 선택하고 Import bone-name mapping and skeleton을 켭니다. 필요하면 .L/.R 쌍 이름 변경도 켭니다.

##### 간단한 예
숫자 이름의 가져온 소매는 포즈 작업이 어렵습니다. 같은 캐릭터의 원본 LOD0 에셋에서 매핑을 생성하고 이름과 Armature 모디파이어가 있는 새 테스트 컬렉션으로 가져옵니다.

##### 확인 및 복구
1.7.1은 대응하는 전체 스킨 웨이트로 식별을 검증합니다. 이전 v1 보조 파일은 v2로 재생성해야 합니다. 상위/형제 폴더의 대체 GLB를 추측하지 않습니다. 근거가 모호하거나 없으면 해결 실패이며 다른 Component의 로컬 본 테이블을 복사하라는 뜻이 아닙니다.

<a id="game-efmi-export"></a>
#### 올바른 스켈레톤 모드로 Endfield Mod 내보내기

세 가지 내보내기 선택은 런타임 번호 체계가 다릅니다. 가져오기 방식과 의도한 런타임 경로에 맞춰 선택합니다.

**위치:** EFMI → Mode: Export Mod.

##### 절차
1. Component Set, 일치하는 Object Source Directory, 별도의 Mod Output Directory를 설정합니다.
2. 아래 모드를 선택합니다. 첫 테스트에는 전체 INI 생성과 텍스처 복사를 유지합니다.
3. [범위와 머티리얼 분리](#game-scope)를 검토하고 무관한 고급 기능은 꺼 둡니다.
4. 내보내고 보고서를 읽은 뒤 게임에서 테스트합니다.

| 모드 | 의미 |
| --- | --- |
| Merged (Unified Vertex Groups) | 공유 편집용 ID를 각 Component의 로컬 런타임으로 역변환 |
| Per-Component | 프로젝트가 이미 각 Component의 로컬 그룹을 사용 |
| Merged (Merged Skeleton) | 공유 편집용 ID/이름을 소스의 확정된 런타임 맵으로 해석해 병합 스켈레톤에 연결 |

##### 간단한 예
Merged로 가져온 프로젝트는 보통 다음 내보내기의 기본값이 Merged Skeleton입니다. 공유 편집과 이전 방식의 Component별 런타임을 의도할 때만 다른 Merged 옵션을 명시적으로 고릅니다.

##### 확인 및 복구
웨이트가 있는 식별자를 해석하지 못하면 내보내기가 중단됩니다. 무관한 매핑을 빌리려고 오브젝트의 Component를 바꾸는 것은 해결책이 아닙니다. 1.7.1은 정확히 해당하는 병합 스켈레톤 리소스에 누락된 shader-resource/unordered-access 기능 플래그를 자동 추가해 폴더명에 따라 가시성이 달라지는 문제를 막습니다. 완전하게 명시된 업스트림 플래그는 유지하며 내보내기는 인터넷을 확인하지 않습니다. 실제 런타임 동작은 따로 테스트하세요.

<a id="game-efmi-lod"></a>
#### Endfield 거리별 LOD 데이터 추가

LOD는 게임이 거리에 따라 사용하는 대체 지오메트리입니다. 근접 캡처만으로 모든 원거리 버전을 설명할 수는 없습니다.

**위치:** EFMI → Mode: Extract LOD Data.

##### 절차
1. 먼저 주 오브젝트를 추출합니다.
2. 원하는 거리의 지오메트리가 실제로 그려질 때 캡처합니다.
3. LOD Frame Dump와 기존 오브젝트 소스를 설정합니다.
4. 우선 기본 매칭으로 추출하고 실패를 읽은 뒤에만 필터나 매칭을 조정합니다.
5. 내보내고 근거리/원거리 전환을 테스트합니다.

##### 간단한 예
수정한 코트가 가까이서는 작동하지만 멀어지면 원본으로 돌아옵니다. 실제로 그려진 원거리 LOD 근거를 소스에 추가한 뒤 다시 내보내고 두 거리를 확인합니다.

##### 확인 및 복구
덮어쓰기는 선택 사항입니다. 충돌하는 LOD 데이터를 교체할 때 오래된 조각이 남아서는 안 됩니다. 매칭되지 않은 Component는 부재로 표시된 전체 디테일 폴백을 유지할 수 있으며 실제 LOD 캡처의 증거가 아닙니다. Allow Export Without LODs는 요구 조건을 우회할 뿐 게임의 거리별 동작을 바꾸지 않습니다.

### Arknights: Endfield · Velo 확장

<a id="game-efmi-crossib"></a>
#### CrossIB로 다른 Component를 통해 소스 지오메트리 그리기

CrossIB는 선택한 소스 지오메트리를 다른 Component의 렌더링 패스에 빌려줍니다. WWMI 다중 씬 병합이 아니며 매핑 화살표에는 정해진 방향이 있습니다.

**위치:** EFMI Export Mod → Cross Index Buffer.

##### 절차
1. 전체 내보내기를 사용하고 CrossIB를 켭니다.
2. 소스에 CrossIB.json v2가 있는지 확인합니다. Generate/Regenerate는 현재의 관련 Frame Dump를 요청합니다.
3. 메시 하나에는 오브젝트 매핑, 계획한 그룹에는 컬렉션 매핑을 추가합니다.
4. 오른쪽 대상 Component를 설정하고 내보냅니다.
5. 게임에서 빌려 쓰는 패스와 일반 파트를 확인합니다.

##### 간단한 예
장식 메시를 호환되는 다른 패스로 그려야 합니다. 왼쪽 소스는 장식이고 오른쪽 대상은 이를 사용하는 Component입니다. 방향을 뒤집으면 다른 결과를 요청하는 것입니다.

##### 확인 및 복구
재생성은 근거 파일 하나를 교체하며 무관한 씬 덤프를 병합하지 않습니다. 대상이 없는 덤프는 유효한 근거를 덮어쓰지 않고 거부됩니다. 매핑이 있으면 내보내기가 200-205 capability ABI를 가진 CrossIBClassifier.ini를 제공합니다. 현재 지원하지 않는 독립 Material Tools 내보내기 레이어와 혼합하지 마세요.

<a id="game-efmi-shapes"></a>
#### Endfield 커스텀 ShapeKey 내보내기

의도적으로 번호를 붙인 키를 런타임 제어로 노출합니다. 번호가 없는 일반 키는 현재 값으로 작성된 기본 형태 조정으로 남습니다.

**위치:** EFMI Export Mod → Advanced → Export Custom ShapeKeys.

##### 절차
1. 내보내기 컬렉션의 메시에 **Deform 12 CapeLift** 같은 키를 만듭니다.
2. Export Custom ShapeKeys를 켭니다. 일반 사용에서는 Merge Buffer Files를 켜 둡니다.
3. 실시간 감지 목록을 확인하고 항목을 클릭해 오브젝트를 찾습니다.
4. 한 오브젝트의 중복 ID와 참여 오브젝트 간 값 충돌을 해결하고 전체 내보내기를 합니다.

##### 간단한 예
Deform 12 CapeLift를 0.375로 설정합니다. 내보내기는 그 값으로 초기화한 지속 변수 **$ShapeKey_12**를 만들고 기본 위치 버퍼는 해당 런타임 키에 대해 중립 상태로 유지합니다. 번호 없는 Fit 키 값 0.2는 대신 내보내는 기본 형태에 베이크됩니다.

##### 확인 및 복구
Deform2Blink처럼 공백/대소문자가 달라도 인식하지만 식별자는 숫자입니다. 하나의 ID는 참여 파트 전체에서 제어를 공유합니다. 병합 버퍼를 쓰면 키 수와 무관하게 각 Component에 추가 병합 파일 두 개가 생기며, 끄면 이전 슬롯별 파일을 사용합니다. UI 요약만으로 런타임 경로가 켜지지는 않습니다.


### Wuthering Waves · 기본 WWMI 작업 흐름

<a id="game-wwmi-extract"></a>
#### WWMI 캐릭터와 텍스처 추출

원하는 지오메트리와 텍스처 형태가 실제로 보일 때 캐릭터를 추출합니다. 한 형태나 거리의 캡처가 다른 모든 상태의 근거는 아닙니다.

**위치:** Game → Wuthering Waves → Mode: Extract Frame Data.

##### 절차
1. 새 Frame Dump와 출력 상위 폴더를 설정합니다.
2. 작은 텍스처, JPG, 알려진 큐브맵, 동일 슬롯/동일 Hash 필터를 검토합니다.
3. 근거에 따라 오래된 상속 바인딩을 제거하도록 Skip Dirty Slots를 유지합니다.
4. 추출 후 대상 오브젝트 폴더, Metadata, 텍스처, ShaderTextureUsage.json을 확인합니다.

##### 간단한 예
우선 근거리 기본 형태를 추출합니다. 대체 형태가 텍스처만 바꾼다면 기본 JSON을 직접 편집하지 말고 나중에 [Form Texture Merge](#game-wwmi-forms)를 사용합니다.

##### 확인 및 복구
유용한 이미지가 필터링되어 없을 수 있습니다. 유효한 근거가 있으면 Dirty Slot 처리는 입증된 특수 상속 서비스 용도만 유지합니다. ‘바인딩된 모든 슬롯 유지’가 아닙니다. 사용 가능한 로그 근거가 없으면 이전 방식 출력을 보존합니다. 얼굴 ShapeKey 데이터가 없다면 보통 얼굴 애니메이션 중 캡처해야 합니다. 검토 없이 고급 누락 데이터 우회를 켤 이유가 아닙니다.

<a id="game-wwmi-import"></a>
#### WWMI 지오메트리 및 소스 미리보기 가져오기

추출한 캐릭터 폴더 하나에서, 크로스 씬 작업이라면 최종 병합 루트에서 가져옵니다. 편집 내내 선택한 스켈레톤 규약을 일관되게 유지합니다.

**위치:** WWMI → Mode: Import Object.

##### 절차
1. 올바른 Object Source Directory를 선택합니다.
2. 버텍스 색상 저장 방식과 Merged 또는 Per-Component 가져오기를 고릅니다.
3. 필요에 따라 Component 하위 컬렉션과 텍스처 가져오기를 켭니다.
4. Mirror Mesh를 원하는 좌우 방향과 일치시킵니다.
5. 가져온 뒤 Component 트리와 버텍스 그룹 이름을 확인합니다.

##### 간단한 예
기본 의상을 Merged로 C0/C1 등의 컬렉션에 가져온 뒤 일치하는 언팩 에셋이 있다면 [원본 본 이름 매핑](#vg-wwmi-map)을 사용합니다.

##### 확인 및 복구
소스 텍스처 미리보기는 ShaderTextureUsage.json을 우선 사용하고 없으면 TextureUsage.json을 사용합니다. 미리보기가 없다고 반드시 지오메트리가 없는 것은 아닙니다. Skip Empty Vertex Groups는 가져온 목록을 바꿉니다. 목록 정리와 로컬/공유 본 식별자 변환을 혼동하지 마세요.

<a id="game-wwmi-skeleton"></a>
#### Merged, Per-Component, from-Merged 내보내기 선택

가져오기는 두 편집 레이아웃을 제공하며 내보내기에는 공유 편집 그룹을 로컬 런타임 그룹으로 변환하는 세 번째 경로가 있습니다.

**위치:** WWMI Import/Export → 스켈레톤 모드.

##### 절차
1. Component 간 공유 그룹으로 편집할 필요가 있는지 결정합니다.
2. 그 편집 규약으로 가져옵니다.
3. 표에서 내보내기 전략을 고릅니다.
4. 게임에서 애니메이션과 관련 다중 캐릭터 조건을 테스트합니다.

| 전략 | 용도 및 장단점 |
| --- | --- |
| Merged | 공유 편집, Component 간 웨이트, 스켈레톤 스케일 지원. 기본 런타임은 갱신이 한 프레임 늦고 동일 대상들이 공존하면 갱신이 멈춤 |
| Per-Component | 로컬 편집/런타임, 한 프레임 지연 없음. 본 범위 제한 및 커스텀 스켈레톤 스케일 미지원 |
| Per-Component (from Merged) | 공유 편집을 로컬 런타임으로 변환. Component별 본 소속을 엄격히 제한 |

##### 간단한 예
공유 그룹으로 쉽게 편집하되 로컬 런타임 동작을 원합니다. Merged로 가져오고 Per-Component (from Merged)로 내보냅니다. 소매가 허용된 Component 맵 밖의 본을 사용한다면 오류를 우회하지 말고 그 영향력을 수정합니다.

##### 확인 및 복구
이미 로컬 ID로 편집한 데이터에 from-Merged를 고르지 마세요. 숫자 이름만으로는 어느 번호 체계에 속하는지 알 수 없습니다. 원본 소스 Metadata와 선택 모드가 일치해야 합니다.

<a id="game-wwmi-export"></a>
#### 완전한 WWMI Mod 내보내기

일반 내보내기는 설정된 컬렉션과 소스에서 완전한 mod.ini 및 필요한 데이터를 만듭니다. Partial Export는 첫 내보내기용이 아닙니다.

**위치:** WWMI → Mode: Export Mod.

##### 절차
1. Component 컬렉션, 프로젝트에 사용한 정확한 오브젝트 소스, 별도 출력을 설정합니다.
2. [스켈레톤 전략](#game-wwmi-skeleton)을 고릅니다.
3. Copy Textures, Write mod.ini 및 유용한 주석을 켜 둡니다.
4. 컬렉션 가시성과 Auto Split by Material을 확인합니다.
5. 내보내고 최종 보고서, Meshes, Textures, mod.ini를 확인합니다.

##### 간단한 예
소매 하나를 바꾼 뒤 테스트 Mod 폴더에 전체 내보내기를 합니다. 빠른 버퍼 전용 갱신을 고려하기 전에 바꾸지 않은 바디와 수정한 소매가 모두 로드되는지 확인합니다.

##### 확인 및 복구
기본 텍스처 교체는 Hash 방식이며 선택적인 Slot은 별도 결정입니다. Auto Split은 일반, from-Merged, Cross-Scene 내보내기 모두에서 전체 파이프라인에 걸쳐 켜짐/꺼짐 규칙을 따릅니다. 소스 오브젝트는 임시 사본에서 준비하므로 모든 편집 오브젝트 이름을 영구 변경할 필요는 없습니다.

### Wuthering Waves · Velo 확장

<a id="game-wwmi-lod"></a>
#### WWMI LOD 데이터 추출

기존 소스에 대체 거리 지오메트리의 근거를 추가합니다. LOD 추출은 별도 패널이며 같은 디렉터리에 일반 기본 추출을 한 번 더 하는 것이 아닙니다.

**위치:** Game → Wuthering Waves → LOD Data Extraction.

##### 절차
1. 주 오브젝트를 먼저 추출한 뒤 원하는 LOD가 보일 때 캡처합니다.
2. LOD 덤프와 기존 WWMI 오브젝트 소스를 설정합니다.
3. 처음에는 기본 매칭을 유지합니다. 필요할 때만 Hash/최소 정점 필터를 사용합니다.
4. 추출 후 전체 내보내기를 하고 거리 전환을 테스트합니다.

##### 간단한 예
머리카락 교체가 가까이서는 작동하지만 중거리에서는 작동하지 않습니다. 중거리 모델을 캡처해 LOD를 추가하고 접근/후퇴를 반복 테스트합니다. 수정된 원거리 결과가 기존 근접 화면을 망가뜨리지 않았는지도 확인합니다.

##### 확인 및 복구
덮어쓰기를 켜지 않으면 기존 LOD를 보호합니다. 고급 매칭에는 복셀/포인트 클라우드 방식, 오차 임계값, 샘플/복셀 크기, 후보 수가 있습니다. 보고된 불일치와 관련된 매개변수를 바꾸세요. 소스 스켈레톤이나 크로스 씬 소스가 바뀌면 이전 리맵을 이식하지 말고 영향을 받는 LOD를 다시 생성합니다.

<a id="game-wwmi-crossscene"></a>
#### 여러 씬의 IB 경로를 하나의 편집 소스로 병합

같은 대상이 서로 다른 씬에서 서로 다른 IB 경로로 렌더링될 때 Cross-Scene Merge를 사용합니다. IB는 텍스처 파일이 아니라 인덱스/드로우 경로를 나타냅니다.

**위치:** Game → Wuthering Waves → Cross-Scene Merge.

##### 절차
1. 기본 추출물과 각 추가 씬의 추출물을 준비합니다.
2. Base를 설정하고 각 소스 행을 추가한 뒤 아래 역할 중 하나를 고릅니다.
3. 새 Output 폴더를 설정하고 Merge across scenes를 실행합니다.
4. 일반 WWMI 가져오기로 병합 루트를 가져오고 내보내기의 Object Source Directory도 이 루트로 유지합니다.
5. 처음 진입할 때와 씬 전환 후에 포함된 모든 씬을 테스트합니다.

| 역할 | 편집 가능해지는 대상 |
| --- | --- |
| Fold into Base | Base 지오메트리가 해당 경로를 대표. 비호환 버퍼는 자체 버퍼 경로를 유지할 수 있음 |
| Editable | 해당 경로가 독립 지오메트리와 별도 식별자를 유지 |
| Merge Form | vb0가 같고 구조가 동일한 추출물이 하나의 Fold 행에 텍스처 형태 근거를 제공. 중복 지오메트리는 추가하지 않음 |

##### 간단한 예
쇼케이스 추출물을 Base로 사용하고 호환되는 월드 경로를 접어 넣습니다. 별도 지오메트리를 가진 실제로 다른 형태는 임의의 텍스처 전용 병합이 아니라 Editable에 속합니다.

##### 확인 및 복구
자체 완결된 루트에는 Metadata, STU, Component 파일, CrossSceneManifest.json v3가 있으며 scene_ibs 하위 폴더가 필요하지 않습니다. 이전 routing-v2 소스는 다시 병합해야 합니다. _ibN 접미사는 소유 관계를 나타내며 두 번째 로컬 Component 번호가 아닙니다. 커스텀/라이브 템플릿과 독립 Material Tools 레이어는 제외됩니다.

<a id="game-wwmi-forms"></a>
#### 지오메트리 복제 없이 다른 텍스처 형태 추가

추가 형태의 원시 덤프에서 텍스처 근거를 기존 소스로 병합합니다. 같은 지오메트리 식별자를 위한 기능이며 독립 편집 가능한 형태를 대신하지 않습니다.

**위치:** Game → Wuthering Waves → Form Texture Merge.

##### 절차
1. 추가 형태의 텍스처가 로드된 뒤 근거리에서 캡처합니다.
2. Form Dump, 현재 Object Source Directory, 일관된 형태 라벨을 설정합니다.
3. Merge Form Texture Data를 실행합니다.
4. 추가 형태나 거리에서도 반복합니다. 같은 형태의 근거를 누적하려면 동일 라벨을, 기본 형태에는 base를 사용합니다.

##### 간단한 예
같은 의상이 강화 상태에 들어가면 텍스처가 바뀝니다. 강화 형태 캡처를 **powered**로 병합합니다. 나중에 같은 상태를 더 먼 거리에서 캡처했다면 가짜 새 형태를 만들지 말고 같은 라벨을 씁니다.

##### 확인 및 복구
이 작업은 STU를 갱신하고 필요한 형태 이미지를 보존합니다. 현재 크로스 씬 루트에서는 하위 STU 파일이 아니라 매니페스트의 Component 매핑을 통해 루트 근거를 갱신합니다. vb0나 구조가 다른 지오메트리는 자체 영역에 속합니다. 정지 화면 하나뿐 아니라 반복 전환과 스트리밍 텍스처를 테스트하세요.

<a id="game-wwmi-anchors"></a>
#### 선택적 형태 앵커를 추가 근거로만 사용

앵커는 특정 형태가 나타났다는 캡처 신호입니다. 이미 안전한 텍스처 분기를 좁힐 수 있지만 로컬 Slot 근거가 근본적으로 모호한 형태를 구분할 수는 없습니다.

**위치:** WWMI Slot compatibility → formid Auxiliary Criterion 및 앵커 찾기.

##### 절차
1. 첫 안전한 Slot 내보내기에서는 옵션을 꺼 둡니다.
2. 필요하면 찾기 도구에 기본 덤프를 설정하고 라벨이 있는 추가 형태 덤프 행을 넣습니다.
3. 후보를 찾아 검토하고 원하는 앵커를 Apply합니다. 캡처를 교체했다면 후보를 초기화합니다.
4. 눈에 보이는 앵커가 없는 형태를 포함해 모든 형태를 테스트합니다.

##### 간단한 예
검증된 형태별 vb0를 허용되는 Hash:label 문법인 **1234abcd:powered**로 적을 수 있습니다. 문법 예시이며 사용자 캐릭터에서 쓸 수 있는 실제 식별자가 아닙니다.

##### 확인 및 복구
수동 식별자로 8자리 vb0 해시와 16자리 픽셀 셰이더 해시를 지원합니다. IB와 버텍스 셰이더 해시는 대체할 수 없습니다. 앵커 없는 형태가 정확히 하나라면 어떤 앵커 형태도 나타나지 않을 때 소거법으로 식별할 수 있습니다. 게임이 바뀌면 갱신하세요. 연관성을 확인하지 않은 UI/VFX 근거를 사용하지 마세요.

<a id="game-wwmi-shapes"></a>
#### 기본 ShapeKey를 교체하지 않고 WWMI 커스텀 ShapeKey 내보내기

어떤 Deform ID가 기본 제공인지는 소스 Metadata가 결정합니다. 커스텀 위치 변화는 별도로 합성하므로 게임의 기본 변형 경로는 유지됩니다.

**위치:** WWMI Export Mod → Export Custom ShapeKeys; 이름 지정은 Mesh Tools.

##### 절차
1. 올바른 오브젝트 소스를 불러오고 [안전한 자동 번호 부여](#mesh-shape-number)를 사용합니다.
2. 커스텀 제어를 쓰려면 Export Custom ShapeKeys를 켜 둡니다. 일반 및 Cross-Scene 내보내기에서 기본적으로 켜집니다.
3. 같은 숫자 ID를 공유하는 참여 키의 값을 일치시킵니다.
4. 전체 내보내기 후 기본 표정과 커스텀 제어를 함께 테스트합니다.

##### 간단한 예
**CapeLift**를 만들고 번호 도구가 해당 소스의 예약 범위 밖에서 ID를 찾도록 합니다. 출력 변수는 **$ShapeKey_<선택한 ID>**이며 Blender 값으로 초기화됩니다. 현재 보이는 키에 1이 없다는 이유로 사용 가능하다고 가정하지 마세요.

##### 확인 및 복구
각 기본 배치는 127개 ID 범위를 예약합니다. 커스텀 내보내기를 끄면 외부 제어가 제거되며 이를 기본 버퍼에 밀어 넣지 않습니다. 유효한 커스텀 변화량이 0이면 빈 리소스를 만들지 않습니다. 번호 없는 키는 현재 값을 Basis에 베이크합니다. d3dx_user.ini에 저장된 값이 새 INI 기본값보다 우선할 수 있습니다. 작성된 값끼리 충돌하면 내보내기가 중단됩니다. Partial Export로는 전체 파이프라인을 갱신할 수 없습니다.

<a id="game-wwmi-raw"></a>
#### Raw Mesh 지오메트리 추출·편집·내보내기

Raw Mesh는 일반 스킨 캐릭터 감지 체인 밖에 있는 적합한 VFX, 배경, 정적 지오메트리를 위한 기능입니다. 캐릭터 추출 오류를 우회하는 범용 지름길은 아닙니다.

**위치:** Game → Wuthering Waves → Raw Mesh Tools.

##### 절차
1. Raw Mesh Extract에서 덤프, 출력 폴더, 쉼표/줄바꿈으로 구분한 VB/IB 해시를 지정합니다.
2. 자동 감지에 명시적 수정이 필요한 경우가 아니면 Position Element를 비웁니다.
3. 추출 후 Raw Mesh를 Import로 바꾸고 생성된 폴더를 고릅니다.
4. 사본을 편집합니다. Export에서 컬렉션, 출력, Auto/Faithful/Rebuild를 고릅니다.
5. 게임에서 의도한 지오메트리와 다른 캡처 효과를 검증합니다.

| 모드 | 변경 가능 범위 |
| --- | --- |
| Auto | 토폴로지가 같으면 충실한 패스스루, 다르면 재구성을 선택 |
| Faithful | 위치를 재인코딩하고 다른 저장 바이트는 보존. 토폴로지는 유지해야 함 |
| Rebuild | 토폴로지 변경 허용. 비표준 데이터는 최선의 범위에서 처리하며 손실 가능 |

##### 간단한 예
캡처한 정적 리본에서 삼각형을 바꾸지 않고 기존 정점을 움직인다면 Faithful이 통제된 실험에 적합합니다. 세분화 추가는 Rebuild가 필요하며 Blender로 표현하지 못하는 속성을 다시 검토해야 합니다.

##### 확인 및 복구
VB 해시는 전체 오브젝트와 드로우를 선택하고 IB 해시는 일치하는 드로우/Component를 선택합니다. 모호한 해시는 거부됩니다. Faithful은 대응을 지어내지 않고 비호환 토폴로지를 거부합니다. 출력은 독립적인 일반 3Dmigoto 오버라이드이며 표준 캐릭터 스켈레톤 런타임이 아닙니다.


### 텍스처 전략 및 공통 내보내기 제어

<a id="game-texture-strategy"></a>
#### Hash, Slot, 캡처된 에셋 이름 매칭 선택

이들은 텍스처 교체가 적용될 위치를 식별하는 방법입니다. 세 가지 이미지 형식이 아닙니다.

**위치:** Game → Export Mod → Velo Compatibility Options.

##### 절차
1. 캡처된 식별자가 여전히 적합하면 기본 Hash 교체로 시작합니다.
2. 스트리밍이나 식별자 변화에 대한 최신 바인딩 근거가 있다면 [Slot 방식](#game-slot)을 고려합니다.
3. WWMI 에셋 이름 매칭은 TextureAssetManifest.jsonl과 함께 캡처하고 다시 추출한 뒤 Use Asset-Name Matching을 켭니다.
4. 첫 로드뿐 아니라 영향을 받는 모든 형태/거리를 테스트합니다.

| 모드 | 필요한 근거 |
| --- | --- |
| Hash | 캡처된 텍스처 리소스 식별자 |
| Slot | 안전한 런타임 분기를 선택할 만큼 충분한 Component/패스 바인딩 및 형식 근거 |
| Asset name, WWMI | 보존되어 내보내는 텍스처 레코드에 기록된 전체 에셋 경로 근거 |

##### 간단한 예
같은 모습의 텍스처도 스트리밍 후 런타임 Hash가 달라질 수 있습니다. 픽셀을 다시 칠한다고 누락된 식별자가 복구되지 않습니다. 해당 상태를 캡처하고 새 근거가 지원하는 전략을 사용하세요.

##### 확인 및 복구
에셋 이름 모드와 Slot 모드는 동시에 사용할 수 없습니다. 에셋 이름 출력은 캡처된 짧은 이름을 사용합니다. 전체 경로가 다른데 짧은 이름이 중복되는 것으로 알려진 경우 거부합니다. 캡처 경로 근거가 없는 레코드는 기본 Hash를 유지합니다. 파일명에서 에셋 경로를 지어내지 마세요.

<a id="game-slot"></a>
#### Slot 텍스처 활성화 및 Component 선택

올바른 Component 드로우 중 교체 이미지를 바인딩하고 이후 이전 텍스처 상태를 복원합니다. 슬롯은 교체 이미지의 색상이 아니라 캡처 근거에서 결정합니다.

**위치:** EFMI/WWMI Export Mod → Slot-style Textures → Slot Export Mode 및 Component 목록.

##### 절차
1. 사용 가능한 ShaderTextureUsage.json과 형식 근거가 있는 최신 소스를 다시 추출합니다.
2. Slot-style Textures를 켭니다. 기본적으로 Native Format Read를 선택합니다. ps-tN->Format 문법에는 XXMI Libs 1.1.0 이상이 필요합니다. Fuzzy Format Matching은 의도적으로 고르는 이전 방식 대안입니다.
3. List components를 클릭하고 Hash를 유지할 항목의 체크를 해제합니다. 수정하지 않은 빈 목록은 처리 가능한 모든 Component를 뜻합니다.
4. 지원 템플릿으로 내보내고 켠 파트와 제외한 파트를 테스트합니다.

##### 간단한 예
바디는 Slot 교체가 필요하지만 특정 액세서리는 Hash 방식이어야 합니다. Mod 전체의 Slot을 끄는 대신 목록을 채우고 액세서리만 체크 해제합니다.

##### 확인 및 복구
새로고침은 기존 선택을 유지하고 새 Component를 선택합니다. 공유 해시는 제외된 소유 파트 때문에 기본 Hash 오버라이드가 여전히 필요할 수 있습니다. 형식 누락, 모호한 분기, 필요한 드로우 범위 근거 누락은 내보내기를 중단합니다. ‘작동할 때까지’ 판별 조건을 넓히지 마세요. 비어 있는 ResourceBypassPST 핸들은 런타임 백업 참조이며 삭제할 쓰레기가 아닙니다.

<a id="game-scope"></a>
#### 내보낼 대상 제어: 이름·컬렉션·머티리얼 분리

내보내기 Component 컬렉션이 작업의 루트입니다. 가시성/중첩 설정은 대상 오브젝트를 정하고 머티리얼 분리는 해당 지오메트리의 할당을 정합니다.

**위치:** Export Mod → Component collection, 무시 옵션, Auto Split by Material.

##### 절차
1. 대상 메시를 설정된 루트 아래에 둡니다.
2. Ignore Nested Collections, Ignore Hidden Collections, Ignore Hidden Objects를 검토합니다.
3. Auto Split을 켰다면 머티리얼 접두사와 계획한 분리 목적지를 확인합니다.
4. 껐다면 전체 내보내기 오브젝트마다 올바른 Component 이름을 붙입니다.
5. 내보낸 뒤 출력 폴더가 비어 있지 않은지만 보지 말고 의도한 모든 오브젝트를 검증합니다.

##### 간단한 예
C0/C1은 하위 컬렉션입니다. 중첩 컬렉션을 무시하면 내보낼 것이 없어질 수 있습니다. 상위 컬렉션이 숨겨져 있어도 보이는 하위 컬렉션이 제외될 수 있습니다. 소매를 분리하고 Outliner에서 옮겼다면 실제 컬렉션 소속이 계속 기준이어야 합니다.

##### 확인 및 복구
분리를 켜면 임시 머티리얼 인식 준비를 사용하고, 끄면 독립 머티리얼 오버라이드를 포함해 전 과정의 머티리얼 분류를 우회합니다. MMD 매핑, ShapeKey, 모디파이어 적용, 스켈레톤 검증을 끄지는 않습니다. 여러 컬렉션에 연결되어 있다면 임의의 숨겨진 연결이 아니라 범위 안에서 보이는 적격 경로를 사용합니다.

<a id="game-advanced"></a>
#### 기본 고급 옵션 이해

고급 스위치는 생성 데이터나 런타임 동작을 바꿉니다. 품질을 높이려고 모두 켜야 하는 체크리스트가 아닙니다.

**위치:** EFMI/WWMI Export Mod → 주 제어 및 Advanced.

##### 절차
1. 정상 작동하는 기준 출력을 보관하고 관련 설정 하나만 바꿉니다.
2. 표에서 해당 제어가 실제로 바꾸는 것을 확인합니다.
3. INI/런타임 동작이 달라지면 전체 내보내기를 합니다.
4. 영향을 받는 조건에서 지오메트리, 애니메이션, 가시성을 비교합니다.

| 제어 | 의미 |
| --- | --- |
| Mirror Mesh | 게임 내 방향에 맞춰 데이터를 미러링. 단순한 오브젝트 Scale X가 아님 |
| Apply all modifiers | 내보내기 중 의도한 모디파이어 결과를 계산. 토폴로지와 ShapeKey 상호작용 확인 필요 |
| Ignore muted ShapeKeys | 관련 계산/내보내기 경로에서 음소거된 키 제외 |
| Add Missing Vertex Groups | 빈 숫자 자리표시자를 채움. 웨이트를 만들지 않음 |
| Fill Missing Mesh Data | 게임별 기본 레이어 추가. WWMI와 EFMI의 기본값이 다름 |
| Skeleton Scale | 선택 스켈레톤 모드가 지원할 때 런타임 모델 크기 조절 |
| EFMI Max Instance Count | 병합 스켈레톤 인스턴스 용량. 사전 메모리 비용 발생 |
| EFMI Spatial Identification | 웨이트 오브젝트에 위치 관련 소유 근거 사용. 임계값은 사용 가능한 고유 Component에 맞아야 함 |

##### 간단한 예
런타임 크기를 시험하려면 지원되는 Merged 모드를 유지하고 1.0에서 조금 바꿔 비교합니다. 무관한 누락 데이터나 식별 스위치를 동시에 켜지 마세요.

##### 확인 및 복구
WWMI의 기존 Unrestricted Custom Shape Keys는 Velo의 독립 커스텀 ShapeKey 스위치와 다릅니다. 누락 데이터 우회는 신뢰할 만한 캡처 근거를 만들어 주지 않습니다. 임시 오브젝트 유지나 Export On Reload 같은 디버그 옵션은 진단용이며 일반 배포용이 아닙니다.

<a id="game-mod-info"></a>
#### Mod 이름·작성자·링크·로고 추가

기존 Mod Info 패널로 전달할 Mod를 설명합니다. 이 메타데이터가 내보낼 지오메트리를 결정하지는 않습니다.

**위치:** EFMI/WWMI Export Mod → Mod Info.

##### 절차
1. Mod Name, Author, Description, Link를 입력합니다.
2. 로고를 쓴다면 **512×512, BC7 SRGB 형식의 DDS**를 준비합니다.
3. Mod Logo로 선택하고 전체 내보내기를 합니다.
4. Textures/Logo.dds와 생성된 메타데이터 참조를 확인합니다.

##### 간단한 예
명확한 의상 제목과 릴리스 안내 링크를 넣습니다. PNG의 확장자를 .dds로 바꾸지 말고 올바르게 인코딩한 로고를 추가합니다.

##### 확인 및 복구
확장자를 바꿔도 이미지 형식이 변환되지 않습니다. WWMI Cross-Scene은 하나의 공유 Mod Info 데이터를 유지하며 각 IB는 자체 등록을 유지합니다. Partial Export는 완전한 메타데이터/에셋을 의도적으로 전달하지 않습니다.

<a id="game-toggles"></a>
#### 간단한 오브젝트 가시성 토글 만들기

INI 토글은 상태 변수를 바꾸고 선택한 상태에서 연결된 오브젝트를 표시합니다. 대화형 GUI 제작기는 아닙니다.

**위치:** EFMI/WWMI Export Mod → INI Toggles.

##### 절차
1. INI toggles를 켜고 Add Var를 클릭합니다. 명확한 이름을 주고 Edit Var에서 충돌하지 않는 단축키를 설정합니다.
2. 상태를 추가하고 오브젝트가 보여야 할 상태에 해당 오브젝트를 추가합니다.
3. 기본 상태를 확인합니다. 익숙해지는 동안 빈 상태/기본 조건을 임시로 표시합니다.
4. 전체 내보내기 후 게임에서 모든 상태를 순환합니다.

##### 간단한 예
**coat_style**을 만들어 한 상태에는 CoatLong, 다른 상태에는 CoatShort를 표시합니다. 바디는 이 선택 밖에 둡니다. 키가 바디를 없애지 않고 두 코트를 전환하는지 확인합니다.

##### 확인 및 복구
공백은 키를 조합하고 세미콜론은 대체 조합을 구분합니다. 고급 조건은 OR보다 AND를 먼저 평가하므로 묶음을 확인하세요. 펼치기/접기는 편집 시 표시만 바꿉니다. 가져오기/내보내기는 편집기의 JSON 텍스트를 사용합니다. 가져오기 전에 Replace/Clear variables를 검토하세요. 변수, 상태, 오브젝트 항목을 삭제하기 전에 작동하는 설정을 백업합니다.

<a id="game-templates"></a>
#### 전체 동작 규약을 유지할 수 있을 때만 커스텀 INI 템플릿 사용

커스텀 Jinja2 템플릿은 생성되는 INI 구조를 대체할 수 있습니다. 기본 출력에 무해한 한 줄만 추가하는 기능이 아닙니다.

**위치:** 일반 단일 소스 Export Mod → INI Template.

##### 절차
1. 일반 작업에는 기본 템플릿을 유지합니다.
2. 의도적으로 템플릿을 개발할 때는 기존 출력 사본을 저장하고 Blender 텍스트 블록 또는 외부 템플릿 파일을 고릅니다.
3. 템플릿 편집기를 열고 통제된 변경을 합니다.
4. 실시간 갱신은 의도한 테스트 출력에 대해서만 시작합니다. 프로젝트를 바꾸거나 다른 Mod를 내보내기 전에 중지합니다.

##### 간단한 예
숙련된 제작자가 개인 테스트 템플릿에 표시용 주석을 추가하고 런타임 변경을 시도하기 전에 생성된 전체 INI를 기준 출력과 비교합니다.

##### 확인 및 복구
오래된 템플릿은 새로 필요한 리소스를 빠뜨릴 수 있습니다. WWMI Cross-Scene은 전용 컴파일러가 다중 IB의 전체 동작 규약을 담당하므로 커스텀/라이브 템플릿을 거부합니다. Slot 변환과 독립 Material Tools 내보내기에도 템플릿 제한이 있습니다. 유지 관리되는 경로로 돌아가려면 기본값으로 초기화하고 전체 내보내기를 합니다.

<a id="game-partial"></a>
#### 통제된 버퍼 갱신에만 Partial Export 사용

이미 완전한 Mod에 선택한 버퍼 종류를 기록합니다. Partial Export는 INI 생성과 에셋 복사를 건너뛰므로 출력만으로는 배포할 수 없습니다.

**위치:** WWMI Export Mod → Advanced → Partial Export → 버퍼 선택.

##### 절차
1. 먼저 정상 작동이 확인된 완전한 출력을 만들고 보관합니다.
2. 정확히 무엇이 달라졌는지, 기존 INI와 변경하지 않은 모든 리소스가 여전히 일치하는지 확인합니다.
3. Partial Export를 켜고 필요한 종류를 선택합니다. 인덱스, 위치, 블렌드, 벡터, 색상, UV 또는 지원되는 형태 데이터입니다.
4. 갱신 결과를 테스트합니다. 배포 전이나 구조/기능 변경 후에는 전체 내보내기로 돌아갑니다.

##### 간단한 예
숙련된 제작자가 기존 Mod에서 호환되는 위치 데이터만 변경하고 위치 버퍼만 의도적으로 갱신합니다. 토폴로지나 드로우 범위까지 바뀌었다면 위치 전용 갱신은 충분하지 않습니다.

##### 확인 및 복구
새 머티리얼 분류, 커스텀 ShapeKey 파이프라인 변경, 새 독립 패키지에는 부분 내보내기를 쓰지 마세요. 이 모드에서 새 INI가 나오지 않는 것은 정상입니다. 버퍼 집합이 어긋났을 때 복원할 수 있도록 이전 전체 폴더를 보관합니다.

### 출력·문제 해결·참고

<a id="game-output"></a>
#### 출력 파일 확인 및 제작자 관리 텍스처 보존

전체 출력에는 보통 mod.ini, Meshes, Textures와 선택적 보조 셰이더가 포함됩니다. 성공 메시지 이후에도 파일과 런타임을 확인해야 합니다.

**위치:** Mod Output Directory 및 게임의 Mod 로더.

##### 절차
1. 최종 보고서를 읽습니다. 검증 오류는 내보내기 실패로 취급합니다.
2. INI가 참조하는 모든 파일이 존재하는지 확인합니다.
3. 이전의 동명 출력 파일이 아니라 의도한 텍스처가 로드되는지 확인합니다.
4. 처음 로드, 재로드, 캐릭터 전환, 각 씬/형태, 필요한 근거리/원거리 상태를 테스트합니다.

##### 간단한 예
같은 이름의 제작자 편집 파일이 이미 출력에 있어 새 소스 텍스처가 보이지 않습니다. [파일 전달 규칙](#material-files)에 따라 보존하거나 의도적으로 갱신한 뒤 다시 테스트합니다.

##### 확인 및 복구
보존된 표준 Component DDS/JPG 텍스처는 추출/내보내기가 관리하지만 직접 만든 마스크 같은 커스텀 보조 이미지는 제작자 책임입니다. 크로스 씬 루트의 표준 정규 파일명은 STU 소유 관계와 일치해야 합니다. 현재 루트에서 원본을 제거하면 새로 생성되는 해당 경로가 제외되지만 이전 출력 파일은 사용되지 않은 채 남을 수 있습니다. 정적 검사로 게임이 교체 이미지를 표시했다고 증명할 수는 없습니다.

<a id="game-troubleshoot"></a>
#### 실패한 단계에 맞춰 문제 해결

실패가 캡처, 소스 생성, Blender 편집, 내보내기, 런타임 중 어디에 속하는지 구분합니다. 무관한 설정을 바꾸지 말고 그 단계를 고칩니다.

**위치:** Blender 작업 보고서, 설정한 폴더, 관련 튜토리얼.

##### 절차
1. 정확한 작업과 전체 메시지를 기록하고 프로젝트 사본을 저장합니다.
2. 증상 표로 다음 확인 사항을 선택합니다.
3. 관련된 최소 변경으로 재현하고 통제된 출력에 다시 내보냅니다.
4. 고친 동작과 이전에 작동했던 동작을 모두 비교합니다.

| 증상 | 먼저 확인할 사항 |
| --- | --- |
| 게임 패널 없음 | 애드온 활성화, 올바른 상단 탭/게임, 업데이트 후 재로드/재시작 |
| Component 오브젝트 없음 | 내보내기 루트, 중첩/가시성, Component 이름 |
| 매핑 누락/오래됨 | 올바른 소스, 최신 추출 또는 v2 본 이름 재생성 |
| 텍스처가 그대로임 | 실제 출력 파일명, 보존된 동명 파일, 선택 원본, 내보내기 모드 |
| Slot 내보내기 차단 | 최신 STU, 필요한 형식, 구분 가능한 분기 |
| 미러가 작동하지 않음 | 로컬 X 방향, 선택 끝점, 잠기지 않은 상호 대응 쌍 |
| ShapeKey 제어 불가 | 번호, 기본 예약 범위, 내보내기 토글, 0이 아닌 변화량, 저장된 값 |
| 다른 씬/거리에서 실패 | 해당 경로/형태/LOD 캡처. 무관한 근거 재사용 금지 |

##### 간단한 예
메시를 합친 뒤 소스 선택기가 빨간색으로 바뀝니다. 정확한 이름이 없어졌다는 뜻이며 웨이트 엔진 실패가 아닙니다. 실제 병합 이름을 선택하거나 의도한 동일 이름의 메시를 다시 만들고 재시도합니다.

##### 확인 및 복구
지원되는 편집 작업은 실행 취소하고 큰 복구에는 저장한 프로젝트/출력 사본을 사용합니다. 다단계 내보내기가 실패한 뒤 출력 폴더가 그대로라고 가정하지 말고 배포 전에 확인하세요. 지원하려는 실제 게임 조건에서의 테스트를 대신하는 도구 결과는 없습니다.

<a id="game-glossary"></a>
#### 꼭 알아야 할 기술 용어

실용적인 파일/작업 개념으로 용어를 익힙니다. 핸드북을 따라가기 위해 렌더링 엔진 전체를 이해할 필요는 없습니다.

**위치:** 다섯 탭 전체의 참고 자료.

##### 절차
1. 튜토리얼에 낯선 용어가 나오면 아래에서 찾습니다.
2. 현재 폴더, 오브젝트, 작업과 연결해 이해합니다.
3. 튜토리얼로 돌아가 대응하는 제어만 바꿉니다.

| 용어 | 쉬운 뜻 |
| --- | --- |
| Component | 추출된 파트/드로우 식별자. 단순히 임의의 메시 오브젝트가 아님 |
| VB / IB | 저장된 정점 데이터 / 삼각형 인덱스 데이터 |
| Hash | 캡처된 리소스 식별자. 보이는 색상이나 보장된 파일명 체크섬이 아님 |
| Slot / ps-tN | 셰이더 드로우 중 사용하는 텍스처 바인딩 위치 |
| Draw / pass | 서로 다른 리소스를 사용할 수 있는 한 번의 그리기 작업 / 렌더링 단계 |
| STU | ShaderTextureUsage.json. 캡처된 텍스처 바인딩 근거 |
| Basis / ShapeKey | 기본 메시 형태 / 참조 형태에서의 저장된 변화 |
| Mapping | 이름 또는 식별자 간 대응표. 웨이트 전송 자체가 아님 |
| LOD | 특정 디테일/거리 수준에서 사용하는 지오메트리 |
| Sidecar | 주 소스 옆에 두는 생성된 보조 파일 |
| Fail closed | 필요한 근거가 불확실하면 몰래 추측하지 않고 중단하는 동작 |

##### 간단한 예
‘이 Component에 안전한 Slot 근거가 없다’는 말은 해당 파트를 그리는 동안 텍스처를 어디에 바인딩할지 도구가 증명할 수 없다는 뜻입니다. PNG가 반드시 손상되었다는 뜻은 아닙니다.

##### 확인 및 복구
예제는 샘플 이름과 번호를 사용합니다. 실제 Component, 본, 슬롯, Hash 식별자는 사용자의 프로젝트에서 가져와야 합니다. 새 기능을 찾을 때는 시간순 릴리스 노트보다 애드온과 동일한 상단 탭과 패널 위치에서 찾으세요.
